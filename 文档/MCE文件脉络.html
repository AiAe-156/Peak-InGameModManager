多语言：三种文字，一条查词顺序

MCE 要翻译的文字有三种来源，但模组名称和界面文字都走同一套词典。界面上显示的每一句，都按下面的顺序从左往右找，找到就停。

先找个人词典config/ModConfigEnhance/language/

你自己改的、补翻的。在概览里双击名称改词，会按需创建 <组名>_personal.txt。

作者词典plugins/<整合包>/MCEPack/language/

跟着整合包一起来的。作者发布时选了哪些语言，这里就有哪些。

内置ModConfigEnhance.dll 内

MCE 自己的界面文字，英文、简体、繁体三份写在代码里。不装任何语言文件也能用。

最后英文原文模组自己写的文字

哪都没找到就显示原文。英文原文同时也是词典左边的键。

词典文件怎样合成一种语言

  • zh-cn.txt 和 zh-cn_补翻_20261010.txt 属于同一组「zh-cn」，按文件名排序读，后读的同名条目覆盖先读的。
  • zh-cn-funny.txt 是独立的一种语言，在下拉里单独出现。
  • 首行写 // display: 简体中文 就是下拉里显示的名字。
  • 语言选择是全局的，切换方案不变；切换整合包也不变，除非这个包存入时选了自己的语言。

补翻是怎么转一圈回来的

  1. 设置侧栏点「导出翻译」或「补漏翻」，文本写到 config/ModConfigEnhance/output/translation/。
  2. 只填等号右边，保留 \n、{0} 这类占位符。
  3. 点「导入补翻」选这个文件，填好的行合进当前语言文件（旧文件先备份）。
  4. 发布整合包时勾选这种语言，这些词条就会进作者词典，跟着包走到玩家那里。

装了 XUnity AutoTranslator 时，MCE 会把选好的语言和词典同步过去，并默认关掉它的在线机翻，让词典说了算。

整合包：一个装着方案和词典的文件夹，外面套上模组

MCE 整合包的核心是一个叫 MCEPack 的文件夹。它不含任何 DLL，只是资料。三种导出方式的区别，在于这个文件夹外面还套了多少东西。点中间的文件看它和别的功能怎么连起来。

作者在游戏里整理

概览里调参数、启停、分组、写介绍、补翻译，再核对每个模组的来源。

同一个整合包可以有多套方案；分组、介绍、媒体、字体由所有方案共用。

MCEPack/ 里的文件

玩家导入和切换

导入只存进整合包库 BepInEx/MCE/packs/，不碰游戏文件。

切换要替换运行中的文件，所以等退出游戏后由更新助手完成，改动前都会先备份。

第一次进主菜单时应用作者指定的默认方案。玩家的修改存进「个人副本」，作者原件保持只读。

三种导出方式

仅作者资料plugins/MCEPack/

只有方案、介绍、译文和来源。给已经装好模组的玩家。

完整本地整合包BepInEx/plugins/<名称>/MCEPack/
+ 所有模组文件夹 + 生成的配置

离线可用。配置文件只根据默认方案里记录的参数生成，不会整份复制你的 config。

雷霆商店包manifest.json 的 dependencies
+ BepInEx/plugins/<名称>/MCEPack/

商店里有的模组写成依赖，其余按你的选择随包附带。

它和其他功能扣在一起的地方

  • 和多语言：发布时选的语言被复制进 MCEPack/language/，成为玩家那边的「作者词典」那一级。玩家导入时可以挑显示语言。
  • 和更新：sources.json 记下每个插件 GUID 对应的商店包，MCE 靠它检查更新。商店包的依赖也是从这里生成的。方案里记的版本是「整合包指定版本」，只在显式恢复时使用。
  • 和签名：signature.json 存公钥和每个文件的哈希。文件被改过时，受影响的作者资料停用，玩家自己的配置不受影响。
  • 和资源包：上传到商店的 MCE 整合包，本身就是一个没有 DLL 的资源包，载荷是 MCEPack/，依赖是那些模组。所以本机 plugins 里那个 MCEPack_6b679869 在概览里显示成资源包。

资源包：有 manifest、没有 DLL 的商店包

BepInEx 只加载 DLL，所以资源包里的文件没人主动去读，要靠依赖它的那个模组按路径去找。MCE 发现一个文件夹里有 manifest.json 却没有 DLL，就标成资源包（青色角标）。停用它就是把 manifest.json 改名成 manifest.json.old。

本机的实例：AeralisFoundation-PLL_Fog_Resources

  • 商店manifest.json0.2 KB
  • 商店icon.png14.6 KB
  • 商店README.md0.9 KB
  • 许可LICENSE.md0.3 KB
  • 载荷NativeFog.bundle6.6 MB

载荷是 PLL 雾效库要读的着色器包。同目录的 Unified_Ray_Tracing 也一样，载荷是一个叫 unifiedraytracing 的文件。

自己发一个资源包要准备什么

  1. ZIP 根目录放商店三件套：manifest.json、256×256 的 icon.png、README.md。
  2. 载荷放在用它的模组会去找的位置，惯例是 plugins/ 下。r2modman 会装进 BepInEx/plugins/<团队>-<包名>/。
  3. 用它的模组在自己 manifest 的 dependencies 里写上这个包，玩家装模组时就会顺带装上。
  4. 不要在 plugins 根目录下再放一份同名的 manifest.json。同一个包两份说明文件版本不一致，就会出现 2.4.4 修掉的「已更新还在提醒」。
