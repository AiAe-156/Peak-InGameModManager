## 共享协议（游戏端与helper两侧引用）

`src/Updating/WorkerProtocol.cs`：主工程默认包含；helper csproj显式Link。无Unity/JSON依赖，可在netstandard2.1使用。带assembly metadata `MCE.WorkerProtocol=2`，不依赖一直固定的产品2.0.0。

- `WorkerProtocol.Current = 2`
- `ValidateTools(directory, requiredProtocol=2) -> string buildHash`：只读验证manifest协议、完整集合及每文件hash。build为有序文件清单摘要（含exe，因此随构建变化）。这是本地发布一致性，不是安全签名/发行者认证。攻击者能重写清单，不应称为可信签名。
- `PrepareTools(source, toolsRoot, requiredProtocol=2) -> string publishedDirectory`：每次先验证本地来源；旧缓存也完整验证；损坏缓存不覆盖；递归复制到 `.stage-<guid>`，验证stage及来源未变化后，Directory.Move原子发布新目录。失败stage保留且永不选用。缓存目录为 `MCE/tools/p2-<build>-<guid>`，管理目录不在包payload里。
- `RequireProtocol(indexSchema, minimum)`：兼容schema1/min1；schema2必须min2；更高版本拒绝。

Overview在写入command前检查来源、index及工具；新command显式 `SchemaVersion=2, MinimumWorkerProtocol=2`（旧helper schema1解析会拒绝，即便尚是旧index）。正常启动强绑定 `--protocol 2`。队列文件仍schema1，新字段WorkerProtocol/WorkerBuild仅宣告实际helper能力。旧命令保持默认protocol1，不隐式迁移index。worker处理入口及saved control均检查协议。

## 给B/C：只读目标内容检查

`Updater/WorkerTargetProtocol.cs`：

```csharp
WorkerTargetProtocol.ValidateTargetContent(string content, int requiredProtocol = 2); // return validated target build hash
WorkerTargetProtocol.RequireCachedExecution(string bepinexRoot);
WorkerTargetProtocol.Initialize();
```

ValidateTargetContent仅从给定content查找唯一 `ModConfigEnhance.dll`，用Mono.Cecil读取 `AssemblyMetadata("MCE.WorkerProtocol","2")`，绝不Assembly.Load/执行；再校验其同目录 `Tools/Updater/worker-protocol.manifest` 和整个发布依赖。目标缺宿主/缺工具/旧metadata均失败，不借当前安装补全、不自动改版本。

B已有 `PackCompleteEnvironment.ManagementProtocolCheck`，E在Program正常入口与QueueWorker构造器Initialize中接入：目标协议检查 + 实际工具必须位于 `root/MCE/tools` 且整套清单有效。B/C独立调用完整环境检查时，需先 `WorkerTargetProtocol.Initialize()`，或直接调用ValidateTargetContent做只读导入预检。发布/预览只想验证目标而不准备实际写入时，应直接ValidateTargetContent，不应借用RequireCachedExecution绕过。

C：完整导入/发布在最终content上调用ValidateTargetContent，任何缺失错误应列为阻断，而不是删掉MCE、借现装或把旧目标改成2。

## 独立恢复CLI（使用已缓存exe）

```text
BepInEx/MCE/tools/p2-.../MCE.UpdateWorker.exe --root <BepInEx绝对路径> --recovery-status
BepInEx/MCE/tools/p2-.../MCE.UpdateWorker.exe --root <BepInEx绝对路径> --recover
BepInEx/MCE/tools/p2-.../MCE.UpdateWorker.exe --root <BepInEx绝对路径> --recover --journal update:<32hex>
# journal也支持 pack:<id> / shop:<id> 或扫描所得的准确绝对journal路径
```

实现为 `QueueWorker.RecoveryOnly`，**不new普通QueueWorker、不Run/Pump/ProcessCommands/ApplySavedControl**；不会消费新commands、启动requested/waiting-exit的新任务、联网下载。持有同一InstallationWriteLease但使用新增 `AcquireWithoutRecovery`，避免status或所选恢复顺便执行enablement恢复。普通Acquire行为保持不变。

支持当前queue引用的未完成普通更新journal、当前pack-task引用的未完成switch journal、当前shop-task的committing/recovery-required journal。仅回滚已有未完成写入，不把installed事务当新rollback请求，不扫描任意脱离任务的历史journal。普通更新复用Transactions.Rollback；包复用PackTransactions.Rollback；商店通过新增helper内ShopQueue partial入口直接复用原Rollback（未修改ShopQueue.cs）。

status检查schema/必需字段/phase/id、路径和链接；update额外绑定root/package/job并验证备份，pack/shop实际执行继续使用原事务范围/备份/ledger验证。损坏、未知或丢journal直接报错保留原件。选择必须命中支持条目，不接受任意文件路径。任何一项损坏会使本次扫描整体失败关闭。

游戏或原任务SourceProcessId还活着时仅输出waiting-exit，不结束进程、不修改queue/journal；回滚内部原有每步Stopped仍防重新启动。独立exe自包含，不需要游戏启动或真实core依赖。`enablement-recovery.bin`不是本入口支持的journal：明确拒绝并保留，不假装已恢复。未引用的孤立历史journal需人工协调，不冒险自动猜测。
