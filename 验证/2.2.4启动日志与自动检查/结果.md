# 启动日志与自动检查减负（2.2.4）

承接 2.2.3（每帧刷新摊帧）。2.2.3 的「未修」清单里点名了三项主线程/跨进程开销，本轮按 FrameDoctor 的 hitch 记录逐条核实后处理。

## 为什么改

2.2.3 之后 `output_log.txt` 里仍有这几条被点名：

| 现象 | 实测 |
|---|---|
| `Overview.AutomaticUpdateChecks.Update` | 单帧 1208 / 1220 / 1230 / 1315 / 1460 ms（均带 GC） |
| `Overview.LogWindow.Update` | 265 / 323 / 367 ms |
| 启动时运行日志面板整屏重播历史 | 31 条早已结束的记录（含「已回退」「已移除记录」「已生效」） |
| worker 每次进程启动都全量扫盘 | 十分钟节流写在进程内存里，而助手是按需启动的独立进程 |
| 「按分组整理预览」静止无进度 | 预览阶段对**全部**已装文件算 SHA256 |

另核实 `OverviewEntry.Update` 单次 441 / 381 ms：日志显示它是**一次性**的 shell/入口预建，且已在主菜单延迟 3 秒之后才发生。按「先事实后改码」，没有剖析数据不改它，见文末「未做」。

## 改了什么

| 文件 | 改动 |
|---|---|
| `src/Overview/OverviewUpdateQueue.cs` | 播报去重表是进程内的，每次启动都为空，于是启动时把队列里所有历史任务挨个重播。现在**本次会话首次看到即为终态、且属纯信息性**的记录（`Completed` / `Removed` / `RolledBack` / `Superseded`）不再播报；回滚真正发生的那一次照旧报，失败与需处理状态照旧报 |
| `src/Overview/AutomaticUpdateChecks.cs` | 原先在主线程 `new OverviewRepository()`——仓库构造内部已扫一遍全部已装程序集、重建方案存储并加载草稿，随后又 `Scan` 第二遍。改用**已应用视图**（`appliedView:true`，顺带跳过草稿与恢复文件写入），并复用重载已完成的那次扫描（`repo.ReloadInstalled`）；被切出安全场景打断的重试复用上一次的准备结果 `_prepared`，正常完成后才丢弃 |
| `src/Overview/OverviewRepository.cs`、`OverviewRepository.Profiles.cs` | 暴露 `ReloadInstalled`，重载时写入该扫描结果 |
| `Updater/InstallStorage.cs`、`Updater/QueueWorker.cs` | 十分钟磁盘清理节流由进程内字段 `sweptAt` 改为时间戳文件 `MCE/maintenance/storage-sweep.stamp`（新增 `SweepDue` / `MarkSwept`）。文件名非 `*.json`，故不会被维护记录清理误删；跨进程生效 |
| `Updater/LayoutPlan.cs`、`Updater/WorkerParallelOperations.cs`、`src/Overview/OverviewPage.Installation.cs` | 目录整理预览不再全量算 SHA256（原先含大量位置已符合、根本不会移动的包）：预览只读路径，哈希推迟到确认落地时**只对本次要移动的文件**计算；每个包目录由走两遍减为一遍（`walkedFiles`）；`Build` 接受进度回调，分阶段把进度同时写日志与任务文件，界面在没有 `ready` 时实时显示阶段进度，不再只有一句静止的「正在准备目录预览」 |
| `src/Diagnostics/LogRepeatIndex.cs`、`src/Overview/LogWindow.cs` | 判定日志内容是否变化改为**逐字段折叠哈希**（`FoldText`），不再为每条记录拼接字符串、也不再 `join` 出分组键；筛选重建时全部分组的排序由三次减为一次（`var groups = _repeatIndex.Groups;`） |

版本号 2.2.3 → 2.2.4，同步 7 处：`src/Plugin.cs`、`manifest.json`、`ModConfigEnhance.csproj`、`Desktop/MCE.Desktop.csproj`、`Updater/MCE.UpdateWorker.csproj`、`README.md`（标题与章节标题）、`CHANGELOG.md`。

## 未做（本轮范围外，如实留待用户决定）

- `OverviewEntry.Update` 441 / 381 ms：日志显示是一次性的 shell/入口预建（主菜单延迟 3 秒后才发生），**没有剖析数据就改它属于赌猜**，故不动。这条需要复现取证（例如在入口预建期间用 FrameDoctor 采样、确认是否真在关键路径上）后再决定。
- worker 进程每 10 秒被拉起一次：本轮只修了扫盘节流失效，**「每 10 秒重启」本身未查未修**。
- `plugins\0核心&基础模组\[界面]ModConfig增强-ModConfigEnhance\` 停用副本未动（删除/迁移属破坏性操作）。
- 帧时间与启动重播无法自测（诊断统一归 FrameDoctor，MCE 内不得加采样）。请启动游戏后查看：运行日志面板是否仍会整屏重播历史记录；概览界面的 `AutomaticUpdateChecks` / `LogWindow` 是否还出现 ≥100ms 的 hitch 行（用 `output_log.txt` 的 hitch 记录复核）。
