# 2.2.11 目录整理预览收尾 + 更新行下载速度与用时

## 现象
截图：「目录整理 · 正在准备文件 · Review folder changes; every move waits for the game to exit.」长期停留，按钮只有商店网页/打开目录/浏览器打开，无取消无下文。

## 取证
- 现场 `BepInEx/MCE/shop/task.json`：`layout-preview`、`State=ready`、0 阻断、`CreatedUtc=2026-11-04T17:25:11Z`、`SourceProcessId=37048`；此后无 confirm。
- 11-08 19:49 日志：2.2.10 启动后三条旧 pending-restart 已按预期收尾（2 superseded、1 completed），但仍每 10 秒 observe——因为这份预览被投影成 `Preparing`，属于 `UpdateStates.Pending`，2.2.10 的「全为待重启才跳过」不成立。

## 代码链（全链路核对）
1. 插件 `PreviewFolderLayout` → `SendLayout(preview)` → worker `PreviewLayout` 写 `preparing-layout` → 分阶段写进度 → `ready`。
2. 插件 `PollInstallationPreview` 见 `ready` 弹 `ConfirmText`：只有「确认」回调；「返回」只关窗。
3. worker layout 只有 preview/confirm，无 cancel、无过期；layout 命令在有更新进行/等待退出时整体延后。
4. `ShopQueueProjection` 默认分支 → `Preparing`；`StoreOperation` 行按钮固定为商店三件套。
→ 返回一次即永久卡住，且让助手持续被拉起。

## 改动
- worker：`CancelLayout`（仅未确认 layout-preview）；layout/local-import cancel 排在「等待当前更新完成」延后之前；未知 layout 操作报错；启动时 `CloseOrphanedPreview`（记录了发起进程且该进程已不在的 ready 预览直接关闭；未记录进程号的不动）。
- 插件：核对窗口「返回」与「有阻断」都发送取消；投影 ready 预览为 `Paused`（不计入 Pending），文案「预览完成 · 等待确认」，按钮「关闭预览」；预览轮询 60 秒不再报超时放弃，改提示等待当前更新；cancelled 结果给提示；补 3 条消息译文。
- 下载速度：`UpdateJob.DownloadSeconds/DownloadTransferredBytes`；worker 以首个回调偏移扣除续传前缀；`StoreClient` 开写前先报起始偏移；队列行版本与百分比之间 10 号灰字「速度 | 用时」，缓存命中/目录整理/旧记录留空、宽度不足隐藏。
