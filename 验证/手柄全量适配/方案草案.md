## 一、事实依据

**游戏原生 UI 绑定**，从现装 PEAK 3.1 的输入动作表里读出（`globalgamemanagers.assets`，UI 输入模块用 `sharedassets0.assets` 的 `UI/Navigate|Submit|Cancel`）：

- 导航：左摇杆 / **右摇杆** / 十字键 → `Navigate`。右摇杆也会移动焦点。
- 确认：A → `Submit` / `UIConfirm`。X 也是 `UIConfirm`，但只有游戏自己的 `MenuWindow` 读它。
- 取消：B → `Cancel` / `UICancel`。
- 切页签：LB / RB → `UITabLeft` / `UITabRight`。
- Start → `Pause`。暂停菜单里按它等于 `GetParentPage`（返回上一页）。
- View → `OpenDebugMenu`。
- 界面上没有绑定的键：**LT、RT、Y、L3、R3**。

**第三方占用**，来自现装模组配置与反编译：

- **peakReconnect 1.0.2**：只要不在 Steam 大厅，按 **LT** 就立即重连上一个房间。在主菜单打开 IGMM 时按 LT 会误触，所以 LT 不能用。
- **ItemSpawnerEnhanced 1.5.0**：View + RT 打开它的窗口。
- **Piggyback 1.4.3**：局内 LB + RB 放下背着的队友。

**IGMM 现有基础**（不推翻）：

- 模组设置页的两级面板、滑条要先按 A 才能调值、按住 0.55 秒才写入绑定、焦点框、滚动跟随。
- 概览的虚拟行在上下移动时保持在同一列；B 逐层关闭。
- 快捷键页：Y 打开键位菜单，右摇杆滚动，提示锚定在控件上。
- 弹窗统一走 `PublicationNavigation`：自动给初始焦点，B 关闭。

## 二、现状缺口

逐项带行号的完整清单见 `手柄键位图.html` 的「现状缺口」。最重要的几条：

1. 作者模式下的多选、拖动排序、拖进分组只能用鼠标。
2. 「模组操作」菜单只能双击打开；分组菜单只能右键打开。
3. 列表里，手柄落焦后弹出的提示框停在上一次鼠标所在位置。
4. 弹窗里的长正文无法滚动，问题报告也无法横向滚动。
5. 未读角标打不开，也无法标为已读。
6. 介绍页不能滚动，也不能点链接。
7. 日志窗：复制选中内容和复制单条记录都要鼠标拖选；导出面板拿不到焦点。
8. 输入框一打开对话框就直接进入编辑态。
9. 屏幕上没有任何按键提示。

### 按住 RT 的功能层（组合键）

RT 在游戏界面里没有任何绑定。按住 RT 期间，IGMM 暂停 EventSystem 的导航，自己处理方向键，所以组合键不会顺带移动焦点。

- **RT + ↑ / ↓**：跳到上一个 / 下一个分组标题（设置页里是分区）。
- **RT + ← / →**：翻页。
- **RT + A**：把本行加入或移出多选（相当于 Ctrl + 点击）。
- **RT + X**：从锚点到本行做范围多选（相当于 Shift + 点击）。
- **RT + Y**：打开所在分组的分组菜单：新建子分组、移到顶层、删除、编辑。
- **RT + B**：清空多选。
- **RT + L3**：全部折叠 / 全部展开。
- **RT + 右摇杆**：三倍速滚动。

**作者模式里的排序**：先用多选选好模组，再按 Y 打开菜单，选「移动」进入搬运态。搬运态下用 ↑ / ↓ 移动插入线，跨过分组标题就是换组；A 确认，B 取消。现成的 `AssignGroup` 和拖放落点逻辑可以直接复用。

**不采用的组合键**：

- 按住 LT 系列：会触发 peakReconnect。
- 按住 LB 系列：LB 单按要用来切页签。
- 双肩同按：与 Piggyback 冲突。
- 按住 L3 / R3：按住摇杆再按别的键几乎做不到。

## 四、交互细节（重点）

### 1. 名称格获得焦点时显示什么

- **默认提示方式是底部详情栏**：列表底部固定一条两行的信息区。第一行是名称、原名、版本；第二行逐条用颜色和文字解释本行的角标，后面接依赖摘要和简介。
- 不用浮框的原因：手柄焦点在上下移动时，浮框会遮住下面的行，位置也跟着跳。
- 「跟随焦点浮框」保留为可选项。选它时，浮框锚定在焦点控件的下沿，不再读鼠标坐标。
- 鼠标悬停的行为完全不变，只有焦点来自手柄时才走新逻辑。判断依据是 `GamepadSupport.IsGamepad` 和 `ISelectHandler` 收到的事件不是 `PointerEventData`。
- 焦点所在行整行底色提亮，再加上现有的米白描边，一眼就能看出焦点在哪一行。

### 2. 小角标的热区放哪

- 8×8 的角标**不做单独的焦点**。角标间距只有 10，逐个落焦既难看又慢，还会打乱上下移动时保列的逻辑。
- **名称格就是这一行角标的热区**：落焦即在详情栏里解释全部角标。
- 按 A 展开详情卡，角标对应的动作在卡里列成可选项：
  - 蓝色：查看变动并标为已读；
  - 绿色：打开版本与更新；
  - 冲突建议；
  - 琥珀色：跳到外层模组。
- 角标固定槽位、颜色、鼠标热区都不动，遵守 `mce-chip-fixed-slots` 的决定。
- 版本列现有的绿色更新点已经能落焦，保留不动。

### 3. 按键提示条

- 列表底部右侧显示当前焦点可用的按键，例如「A 详情　X 停用　Y 更多　RT 功能　B 返回」。内容随焦点所在的列变化。
- 只在手柄态下显示；View 键可以隐藏。
- 图标优先借用游戏的 `InputSpriteData` 精灵，按 Xbox / PS 自动切换。拿不到时退回文字圆标。

### 4. 输入框

- 所有对话框统一走 `MarkSelectable`：选中后不自动进入编辑，按 A 才编辑。要删掉 `OverviewUi.cs:289` 直接调用 `ActivateInputField` 的写法。
- **Steam 大屏幕模式或 Steam Deck** 下，按 A 弹出 Steam 屏幕键盘。用的是 `SteamUtils.ShowGamepadTextInput`，游戏的加入房间页就是这么做的，提交后回填输入框。
- 普通桌面模式下仍然需要键盘，不再额外提示。

### 5. 右摇杆只滚动

- 在 IGMM 页面内，右摇杆有输入时，本帧让 `Navigate` 忽略右摇杆，只按我们的滚动逻辑处理（快捷键页和使用说明页已有这段逻辑）。
- 焦点滚出视野后，下一次按方向键，焦点先回到视野内的对应行，避免画面猛地跳回去。

### 6. 弹窗

- 长正文区补一个可落焦的「阅读区」：右摇杆随时可以滚动；问题报告里右摇杆左右做横向滚动。
- 有多层的窗口按 B 先关上层。例如日志窗的导出面板，按 B 只关面板。
- 管理中心、更新队列这类多页窗口，用 LB / RB 切页。

### 7. 日志窗

- 改成「按条选择」：A 选中一条，RT + A 追加多条，然后复制选中内容或复制单条。
- 字符级的自由拖选不做。

### 8. 介绍页

- 只做阅读：右摇杆滚动，十字键在链接和图片之间切换，A 打开，X 放大图片。
- 编辑仍然需要键鼠。

## 六、实施分批（建议）

1. **基础设施**：
   - 统一的 `GamepadIntent` 输入层，负责 RT 功能层、暂停导航、右摇杆只滚动、长按加速；
   - 焦点来源判断，以及列表提示改为锚定控件；
   - 底部详情栏和按键提示条。
2. **概览列表**：
   - 名称格的 A 详情卡、X 启停、Y 更多菜单、RT 组合键；
   - LB / RB 切页签，L3 折叠；
   - 作者模式的搬运态。
3. **弹窗与窗口**：阅读区、多层窗口的 B、多页窗口的切页、输入框统一改为按 A 才编辑、Steam 屏幕键盘。
4. **长尾**：日志按条选择、介绍页阅读、更新队列详情、颜色删除钮、未读角标标为已读。
5. **验证**：
   - 纯逻辑夹具：组合键状态机、搬运态落点；
   - 源码断言：禁止新增 `Mouse.current.position` 定位提示，禁止直接调用 `ActivateInputField`；
   - 三语使用说明补一节「手柄操作」。

**需要实机确认**：右摇杆目前是否同时滚动又移动焦点；PS 手柄的精灵切换。
