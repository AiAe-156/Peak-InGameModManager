调查日期 2026-11-10。目录前缀约定：`反编译\` = `F:\Games\SteamLibrary\steamapps\common\PEAK\MODs\反编译\`，`MCE\src\` = `F:\Games\SteamLibrary\steamapps\common\PEAK\MODs\ModConfigEnhance\src\`。

## 结论

1. **小数显示回归已坐实，根因在游戏本体 `Zorro.Settings.UI.FloatSettingUI`**：3.1.0 把四处显示调用从 `FloatSetting.Expose(value)`（`ToString("F")`，两位小数）全部改成了私有方法 `FloatSettingUI.GetFormattedString(float)`，而它对 `DisplayType.Number`（默认值）返回 `value.ToString("0")`。PEAKLib.ModConfig 1.8.2 的 `BepInExFloat` / `BepInExDouble` 继承 `FloatSetting`，`BepInExFloat_SettingUI` 继承 `FloatSettingUI` 并调 `base.Setup`，所以原样继承了取整显示；这与用户实测的 `0.35→0`、`1.25→1` 吻合。
2. **不止显示，手打输入也会被破坏（代码推导，未实机复现）**：`OnChanged` 每敲一个字符就用 `GetFormattedString` 回写文本，敲 `0.` 时文本被回写成 `0`，小数点被吞，`1.25` 会变成 `125`（再被夹到上限）。滑条拖动本身不取整，存盘值是全精度的，只是显示成整数。
3. **推荐修法**：MCE 对 `FloatSettingUI.GetFormattedString(float)` 打一个 Harmony 前缀，仅当 `_listeningSetting is IBepInExProperty`（即 ModConfig 创建的设置）时接管：输入框正在编辑时原样返回当前文本，否则按 `"0.###"` 输出。原版设置（FOV、鼠标灵敏度、音量）不受影响，保持开发者的新显示。放在 MCE 而不是 LocalFix（理由见「修复方案」）。
4. **菜单配色变化也已确认，是预制体与代码两处同时改**：`SettingsCell` 预制体里 Image 的颜色已经是深海军蓝 `(0.071,0.182,0.283,0.729)`，`SettingsTABSButton` 新增 `Awake` 把页签底色设为同一蓝并改了选中/未选中文字色。MCE 的纸面底图 sprite 与材质来源没变，但 MCE 自己写死的棕色 `TabBackground`、页签选中色（白底黑字）与新原版不一致。
5. **其他适配点基本无硬故障**：MCE 打补丁或反射的游戏类型全部仍在；唯一需要实机复核的静默风险是新增的 `GamepadSlider`（绕过 MCE 手柄滑条门控的路径）。**注意：现存日志都是更新前最后一次运行（11-09 21:38）留下的，更新后游戏还没启动过，所以所有「日志里没有告警」的结论都不能算数。**

## 小数显示回归：根因（新旧代码对照）

旧版为 `反编译\Zorro.Settings.Runtime_PEAK_v2.6.b_2026-10-07\Zorro.Settings.UI\FloatSettingUI.cs`，新版为 `反编译\Zorro.Settings.Runtime_PEAK3.1.0_2026-11-10\Zorro.Settings.UI\FloatSettingUI.cs`。两个归档之间 `Zorro.Settings` 只有三个文件不同：`FloatSetting.cs`、`VolumeSetting.cs`、`FloatSettingUI.cs`。

**旧（2.6.b）**，四处显示全走 `floatSetting.Expose(...)`，而 `FloatSetting.Expose` 是 `result.ToString("F")`（`FloatSetting.cs:80-83`，新旧相同）：

```csharp
inputField.SetTextWithoutNotify(floatSetting.Expose(floatSetting.Value));          // Setup
...
inputField.SetTextWithoutNotify(floatSetting.Expose(result));                      // OnChanged
slider.SetValueWithoutNotify(result);
floatSetting.SetValue(result, settingHandler, fromUI: true);
...
inputField.SetTextWithoutNotify(floatSetting.Expose(value));                       // OnSliderChanged
...
inputField.SetTextWithoutNotify(floatSetting.Expose(floatSetting.Value));          // OnSettingChangedExternal
```

**新（3.1.0）**，`FloatSettingUI.cs:13-28`、`30-51`、`60-69`、`70-89`：

```csharp
private FloatSetting.DisplayType _displayType;                                      // :13
...Setup:   _displayType = floatSetting.GetDisplayType();                           // :21
            inputField.SetTextWithoutNotify(GetFormattedString(floatSetting.Value)); // :25
            inputField.onEndEdit.AddListener(FormatAsPercentage);                    // :28
OnChanged:  float num = result;                                                      // :38
            if (_displayType == Percentage) num = result * 0.01f;                    // :39-42
            else if (_displayType == HalfPercentage) num = result * 0.02f;           // :43-46
            inputField.SetTextWithoutNotify(GetFormattedString(num));                // :47
            slider.SetValueWithoutNotify(num); floatSetting.SetValue(num, ...);      // :48-49
OnSliderChanged / OnSettingChangedExternal 同样改走 GetFormattedString               // :55 / :65
private void FormatAsPercentage(string text) {                                       // :70-76
    if (float.TryParse(text, out var result)) { GetFormattedString(result); }        // 结果被丢弃，等于空操作
}
private string GetFormattedString(float value) {                                     // :78-89
    if (_displayType == Percentage)     return Mathf.Round(value * 100f).ToString("0") + "%";
    if (_displayType == HalfPercentage) return Mathf.Round(value * 50f).ToString("0") + "%";
    return value.ToString("0");                                                      // Number（默认）：取整
}
```

配套新增（`FloatSetting.cs` 新版第 10-15 行与 85-88 行）：`enum DisplayType { Number, HalfPercentage, Percentage }` 与 `virtual DisplayType GetDisplayType() => Number`。`VolumeSetting.GetDisplayType()` 返回 `Percentage`（`VolumeSetting.cs` 新增段）；`MouseSensitivitySetting.cs:30-33` 与 `ControllerSensitivitySetting.cs:30-33` 返回 `HalfPercentage`。原版里只有这三类被设成百分比，其余原版浮点（FOV、FPS 上限、额外 FOV 等）走 `Number`，也就是取整，这正是补丁说明里「不带小数」的含义。

用户在 `ModConfigEnhance\验证\PEAK3.1兼容核查\probe.log:169` 的实调结果（`ACTUAL_FORMAT 0.35=0 1.25=1`）与上述代码完全一致。

**输入编辑也受影响（代码推导，未实机复现）**：`OnChanged` 绑在 `inputField.onValueChanged` 上，每个字符都触发。以 `Number` 类型敲 `1.25`：
- 敲 `1` → 解析为 1，文本回写 `"1"`，设置值 1；
- 敲 `.` → 文本 `"1."`，`float.TryParse("1.")` 为真，值 1，文本被回写 `"1"`，小数点丢失；
- 再敲 `2`、`5` → 变成 `"125"`，设置值 125，被 `Clamp` 夹到 `MaxValue`，并经 `SetValue` → `handler.SaveSetting` → ModConfig 的 `saveCallback` 写进 `ConfigEntry.BoxedValue`。

整段粘贴 `0.35` 则存的是 0.35，只是显示成 `0`。旧版同一路径回写的是 `Expose` 的 `"F"`（`1.00`），不吞小数点，所以此前能手打。滑条路径（`OnSliderChanged`，`:52-57`）把原始 float 直接 `SetValue`，**存盘值不取整，只是显示取整**。因此「保存的数值被破坏」只发生在手打输入。

## ModConfig 与 MCE 现状

### ModConfig 1.8.2 的浮点设置

- `PEAKLib.ModConfig.SettingOptions.BepInExFloat : FloatSetting`（`反编译\PEAKLib.ModConfig_1.8.2_PEAK3.1.0_2026-11-10\PEAKLib.ModConfig.SettingOptions\BepInExFloat.cs:13`）。`GetSettingUICell` 返回自己缓存的克隆：`Instantiate(SingletonAsset<InputCellMapper>.Instance.FloatSettingCell)`，取出克隆上的 `FloatSettingUI`，加 `BepInExFloat_SettingUI`（借用 `slider`、`inputField`），再 `DestroyImmediate` 原 `FloatSettingUI`（`:21-42`）。

- 范围来自 `AcceptableValueRange<float>`，没有范围时回退 0–1000（`BepInExFloat.cs:87-94`）。`BepInExFloat` 没有覆盖 `GetDisplayType`，用基类默认 `Number`。

- ModConfig 注册 float/double 在 `PEAKLib.ModConfig\ModConfigPlugin.cs:227-241`。

### MCE 当前碰到这条路径的地方

## 修复方案

### 推荐：MCE 里对 `FloatSettingUI.GetFormattedString` 打 Harmony 前缀

- **目标方法**：`Zorro.Settings.UI.FloatSettingUI`（程序集 `Zorro.Settings.Runtime`）的 `private string GetFormattedString(float value)`，实例方法，一个参数。用 `AccessTools.Method(typeof(FloatSettingUI), "GetFormattedString", new[] { typeof(float) })` 取得，取不到就记警告并整项不挂（与现有补丁风格一致）。四处显示、输入、滑条、外部更新都经过它（`FloatSettingUI.cs:25/47/55/65`），所以一个补丁就够。
- **前缀签名**：`static bool Prefix(FloatSettingUI __instance, float value, ref string __result)`。
  - 区分 ModConfig 与原版：`__instance._listeningSetting is IBepInExProperty`。`_listeningSetting` 是 `SettingInputUICell` 的 protected 字段，在 `Setup` 里 `RegisterSettingListener(setting)` 先于第一次 `GetFormattedString` 赋值（`FloatSettingUI.cs:20` 先于 `:25`），MCE 编译时已 `Publicize` 游戏程序集，`ChangeLedger.cs:152` 已经这样用。`IBepInExProperty` 是 ModConfig 的 internal 接口，MCE 工程已对 ModConfig 设 `Publicize="true"`（`ModConfigEnhance.csproj:51`）。
  - 不能用 `__instance is BepInExFloat_SettingUI`：那样会漏掉 `BepInExDouble`（用的是裸 `FloatSettingUI`）。
  - 命中时才 `return false`，其余一律 `return true` 交还原版，原版设置的新显示（含百分比）原样保留。
- **精度规则**：
  - 先用 `value.ToString("0.###", CultureInfo.CurrentCulture)`（最多 3 位小数、去尾零），与 MCE 说明面板 `FormatValue`（`ModConfigDescriptionPanel.cs:792-799`）一致，且与 `OnChanged` 里的 `float.TryParse(str)`（当前区域设置）互相可解析。
  - 不必读 `AcceptableValueRange` 的步长：ModConfig 滑条是连续的，没有 step，条目里也没有精度元数据。可选的细化是区间跨度 ≤ 1 时用 `"0.####"`，但不是必须。
- **编辑期间不要回写**：前缀里若 `__instance.inputField.isFocused`（用户正在这个输入框里打字），直接 `__result = __instance.inputField.text; return false`，这样 `OnChanged` 的 `SetTextWithoutNotify` 等于写回原文，不吞小数点，不会把 `1.25` 变成 `125`。
- **失焦时整理文本**：原版 `onEndEdit` 挂的 `FormatAsPercentage` 是空操作（`FloatSettingUI.cs:70-76`），所以失焦后文本不会被格式化。可再加一个对 `FloatSettingUI.Setup` 的 Postfix，仅对 ModConfig 设置给 `inputField.onEndEdit` 加一个监听，用 `SetTextWithoutNotify(格式化后的当前值)` 整理一次。这一步是体验项，可后做。
- **风险与注意**：
  - Mono 可能内联小方法，该方法含三个分支和字符串拼接，不太可能被内联；MCE 在 `Awake` 阶段打补丁，早于任何设置 UI 的 JIT。仍应在实机确认补丁生效（挂载日志加一行 `[设置页] 小数显示补丁已挂载`）。
  - `isFocused` 路径下，若同时有外部更新（`OnSettingChangedExternal`，如 MCE 应用方案）会返回旧文本，影响极小；要更稳可在前缀里判断「文本能解析成当前 `value` 才原样返回」。
  - 打补丁点依赖游戏私有方法名，游戏再改会静默失效，所以要有挂载失败的警告日志，并写进回归的源码断言。
  - 不触碰 `SetValue`、存盘值与 `ConfigEntry`，因此不需要数据迁移。

### 备选

1. **改 ModConfig 的设置类型**（让 `BepInExFloat` 覆盖 `GetSettingUICell` 返回自带的 UI 组件，不再继承 `FloatSettingUI`）：改动在上游 PEAKLib.ModConfig，MCE 不能改别人的 DLL；若在 MCE 里替换已克隆的组件则要重建 `slider/inputField` 引用并和 `BepInExFloat_SettingUI`、`ChangeLedger`、`GamepadSupport` 的取用方式对齐，改动面大于一个前缀。不推荐。
2. **MCE 自己在 `ShowSettingsPostfix` 之后画一个小数值标签覆盖输入框**：要再维护一份与输入框同步的 UI，会与游戏自己的输入框抢焦点，手柄与翻译也得另管。不推荐。
3. **等上游 PEAKLib.ModConfig 更新**：最干净，但时间不可控，且用户已经遇到了编辑被破坏。可以作为长期方案并行向上游反馈，MCE 的补丁待上游覆盖 `GetDisplayType` 或自带格式化后即可摘除。

### 归属：放 MCE，不放 LocalFix

- 分区规则（`MODs\AGENTS.md`）是「新的模组冲突修复加进 LocalFix 分区」。但 LocalFix 的第 9 分区（模组设置面板）已在 2.17.0 整体迁出为 MCE（`LocalFix\README.md:235-240`、`:306`），LocalFix 现在没有任何 ModConfig 相关代码，也不引用 PEAKLib。
- 这个回归发生在 MCE 已经重排、翻译、加手柄支持的那一页，且只在装了 ModConfig 时才出现；MCE 又是白名单基础组件，必装 ModConfig，已有 `ModConfigSupport.TargetVersion` 版本门禁（`ModConfigSupport.cs:25`）。放在 MCE 的 ModConfig 补丁区、与 `ModConfigTreeLayoutPatch` 同批挂载最顺。
- 这是需要你拍板的一项：规则字面上偏向 LocalFix，但依赖关系偏向 MCE。

### 建议

**推荐：默认跟随游戏新外观，运行时读原版颜色，缺失时回退旧棕色；是否同时给一个「经典棕色」开关请你定。**

- 理由：纸面样式已经是运行时抄原版的，配色继续写死棕色就违背了「与原版一个手感」的初衷；原版把单元格预制体直接改蓝了，我们没法让 ModConfig 右栏变回棕色，而不改它，左栏棕、右栏蓝就是永久不一致。
- 具体改动位置：
  1. 新建一处统一来源（例如 `ModConfigLook`），用 `AccessTools.TypeByName("Peak.UI.SettingsMenu.SettingsColors")` 读 `BoxColor`/`TextDefaultColor`/`TextSelectedColor` 三个静态字段，读不到（旧游戏版本）就回退现有常量；
  2. `ModConfigTreeLayoutPatch.cs:81` 的 `TabBackground` 改为取这里的 `BoxColor`；其 7 处引用（见上表）自动跟随，但要核对半透明度（`0.92`、`0.4` 这类派生值在 `ModConfigSidebarWidgets.cs:411,485`）；
  3. `ModConfigTreeLayoutPatch.cs:873` 与 `:964`：选中文字由 `Color.black` 改为 `TextSelectedColor`，未选中由 `Color.white` 改为 `TextDefaultColor`；
  4. `TimeThemeBridge.cs:236`：白天选中底图目标由 `Color.white` 改为 `TextDefaultColor`（米色），夜间格仍用 TimeTheme 的 `DarkSelectedFill`；
  5. 夜间：TimeTheme 表里没有蓝色，因此 MCE 自建元素要靠自己的 `ThemeTint(day, night)`（`ModConfigSidebarWidgets.cs` 的 `Tint(background, Cream, TabBackground)` 一类）给蓝色配一个夜间对应色，或者在夜间继续用 TimeTheme 的黑；这个取舍需要你看实机效果；
  6. `UiActionStyle` 的 Neutral（`:27`）与概览窗口的 `Brown` 可保持不动，或另行决定。
- 不推荐：保持棕色不动（与原版、与 ModConfig 右栏都不一致）；也不推荐一上来做成大量可调项，只给一个二选一开关即可。
- 动手前必须在游戏里截一张设置页对照，因为资产层「以前是棕色」我无法独立证实。
