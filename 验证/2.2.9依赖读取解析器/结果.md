# 2.2.9 卸载误报「依赖信息不完整」

## 现象
2.2.8 部署后实测（截图 5.png，12:41），天阶的维护菜单「卸载（安全预览）」仍是灰的，文案「依赖信息不完整，暂不能卸载」。

## 取证
- 该文案是 `DiagnosticSummary.Status.Incomplete`，出口是 `Capability.CanUninstall=false` 且 `ProtectionPath` 为空——与 2.2.8 修的 `RequiredByMce` 不是同一条。
- 日志写 `Mod Manager (In-Game) 2.2.6` 是 `Plugin.PluginVersion` 常量漏升版；现装 DLL 是 03:12 部署的 2.2.8（含 `MceRequiredIdentities`）。
- `probe/` 链接**真实** `ComponentDependencyCollector.cs` / `ComponentDependencyGraph.cs` / `PluginFileNames.cs`（仅桩 `PackageRules.IsLoader`），对现装 `BepInEx` 只读跑：
  - 修前：范围失败 64 条，其中 23 条 `Failed to resolve assembly: 'BepInEx, Version=5.4.23.3'`；已识别包 24 个中 4 个被判 Incomplete（PEAKLib_Items、TimeTheme、PlantholderOverhaul、So_Fly）；带确认文件的天阶 `CanUninstall=False`，原因「Target component identity or metadata is unverified」。
  - 根因：读 `BepInDependency` 的第二个构造参数要解码 `DependencyFlags` 枚举（在 BepInEx.dll），`ReadAssembly` 没配解析器。
- 修后同一跑：BepInEx 解析失败 0；被挡 0；天阶 `CanUninstall=True, VerificationRequired=True`（进入安全预览）。剩余 42 条 Manifest evidence 失败是探针自己的 manifest 读取器比插件侧严格所致，不影响结论。

## 改动
- `ComponentDependencyCollector.Collect`：`DefaultAssemblyResolver`，清空默认搜索路径，只加 `BepInEx/core` 与游戏 `PEAK_Data/Managed`；新增可选参数 `gameRootPath`。
- 插件侧 `InfrastructureDependencyCollector` 传 `Paths.GameRootPath`；worker `ShopComponentProtection` 传 `Files.GameRootFor(root)`（管理器档案下 BepInEx 父目录不是游戏根）。
- 版本 2.2.9（三个 csproj、manifest、`PluginVersion`、README、CHANGELOG）。
- `验证/2.2.8保护清单与角标统一/source_checks.py` 的版本断言由钉死 2.2.8 改为格式 `2.2.x`。

- 三项构建 0 警告 0 错误；`source_checks.py` 7 项通过；2.2.8 夹具 graph 7 项 + 源码 4 组通过；完整回归 23/23。
