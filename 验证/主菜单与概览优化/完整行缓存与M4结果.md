# 完整行缓存与 M4 发布去重结果（2026-10-30）

## 本轮结果

采用任务允许的**稳定身份小型 LRU 完整控件树缓存**，替换原 row shell 池。不是跨身份通用 rebind 控件池，也不是保留壳再销毁全部子控件。

- 普通模组、组件、分组标题分别缓存最多 **24 / 12 / 12 个闲置完整行树**；活跃树由视口 + 上下 2 行缓冲 + 当前焦点/拖动源决定。
- 离屏：隐藏提示、停用完整 GameObject 树、移出 content 到 root，保持同一数据身份、所有子控件和监听；再次可见：移回 content、恢复位置并启用，**不调用 Bind，不再 AddListener**。
- 缓存按行模型对象持有身份，同一结构代次内不把任何旧监听转给另一 mod/component/group。完整模型仍保留所有行，业务、范围选择、完整模型导航不裁剪。
- 闲置预算超限时淘汰最久未使用的整行；淘汰才失效租约、清提示/导航/拖动/Button/Toggle 回调并销毁完整树。不会把残留 shell 再交给另一身份。
- 分组标题和基础组件组标题都由 AddVirtualRow 纳入逻辑高度、可见范围和完整模型导航。缓存标题不参与离屏 drop 命中；普通/作者模式原来的标题颜色、菜单、折叠、双击编辑和 drop 行为不改。
- 焦点与两种拖动源仍钉住原对象；复用后颜色按当前选择重算。绿点、菜单、范围选择及不同作者模式沿用原绑定；版本/来源显示 stamp 变化销毁该身份树，下一次可见重建，不复用过期显示。

### 常驻边界与取舍

逻辑常驻完整树数量 = 活跃（视口+缓冲+最多当前焦点/拖动源） + 闲置最多48。Unity 的 Destroy 在帧尾执行，淘汰树立即停用，实际内存瞬时可能额外包含本帧待销毁树，不声称任意时刻 native 对象绝不超过该数字。

结构变化（搜索、折叠、语言、方案、作者模式、宽度重新布局等触发 Render）**作废整个结构代次并安全销毁旧树**，不跨代次复用捕获了旧布局/配置/集合的闭包。这是明确的安全设计取舍，不是已完成通用可重绑定叶控件池。连续滚动在缓存命中内不会重建子树；遍历超过缓存容量后返回淘汰行需要重建。该方案满足本任务认可的稳定身份 LRU 路线，不宣称所有路径均零分配。

## M4 助手发布审查

- `QueueWorker.Run` 的稳定 idle / 游戏仍运行 waiting 路径没有周期 Save。构造/退出需发布 WorkerProcessId，是实际状态变化，不应消除。
- PackQueue/ShopQueue 常态/等退出路径也提前 return，不周期重写；下载写进度已有节流。事务日志必须实时保留，本轮不去重事务提交/恢复记录。
- `QueueWorker.Save` 新增 `StateChangePublication`：按锁内完整序列化内容判断是否变化，重复 Save 不写文件、不增加 Revision；成功后记录提交后 Revision 的内容。写入失败回滚内存 Revision，保持可重试，不吞错误。
- 无变更 Save 仍有一次序列化比较开销，但 Run idle 不调用 Save；未加心跳、未改协议/来源/安装路径。
- **协调点**：本轮仅改 Updater/QueueWorker.cs 的 Save 方法并新增 StateChangePublication.cs；未触碰来源/导入/商店/Files 等其他 Updater 文件，主代理集成时保留这两项即可。
