# 主菜单空闲与模组概览最终优化方案

- 日期：2026-10-30
- 主项目：ModConfigEnhance（界面名称 Mod Manager / 模组管理器）
- 状态：**实施中**。后续会话用户已明确确认跨工作区修复并部署；实际完成项、离线结果与部署状态以本目录实施结果及 deployment JSON 为准。
- 本次修订：按用户反馈，将来源自动识别、雷霆商店核验、版本检查和简洁结果展示升级为独立深度重构主线；替换前版混合分类统计方案。
- 基线：PEAK 3.0.1 / Unity 6000.3.15f1；取证会话 `BepInEx/FrameDoctor-Logs/2026-10-30_15-44-21/`。
- 用户最新范围：只处理本地自研／接手维护的目标工程；其他第三方模组本轮不处理。UBImGui 是唯一新增第三方例外，收益经验证值得处理时，由 LocalFix 承载补丁。

### 必做

### 条件项

- 本轮开发保持真实用户配置、签名作者包、库存、更新队列和安装位置。未来产品自动核验维护独立、可再生的来源缓存；用户明确的来源选择由用户操作修改并保留备份。

## 二、现有证据与优化重点

`output_log.txt` 中的场景为 `Pretitle → Title`，两次角色扫描均为 0，之后在原生设置与 MCE 概览之间切换。后台成本发生在主菜单会话中。

以下是已记录入口剔除 ≥30ms 长调用后的常态均值，用于排优先级；分项工作由实施阶段计数器继续拆分。

| 入口 | 现有成本 | 已定位行为 |
|---|---:|---|
| 复活传送 `ReviveController.Update` | 约 2.49ms/帧 | 先查找 PlayerConnectionLog，之后才判断角色和按键 |
| 麦克风 HUD 等待 | 约 0.95ms/帧 | 两条等待协程，每条每帧 GameObject.Find |
| 玩家距离 `Plugin.LateUpdate` | 约 0.37ms/帧 | 零角色仍进行显示维护；主相机缺失时每 0.5 秒重试 |
| UBImGui Update＋帧尾入口 | 约 0.15ms/帧 | 无窗口需求门控，持续输入和渲染帧处理 |

MCE 的直接证据：

- 普通提示显示时每帧测量文本；依赖提示跨行时重复建立显示索引、格式化和测量。
- 稳定段约 467 次字体维护、231 次按钮布局、231 次按钮样式、63 次状态标记回调／帧。
- 列表按全体行创建，刷新时销毁重建，并强制刷新 Canvas。
- 更新队列及相关文件约 441KiB，每约 400ms 重新解析。
- 16:03:37 更新检查结束，列表刷新 226ms，随后一帧 249ms，该帧 GC 计数为 0。
- 全会话 937 次 >50ms 卡顿中，865 次被宏观计数器归为 GC 主导；内存压力应与 CPU 工作同时治理。

更新数量根因：61 个已加载插件中，27 个为商店来源，合并为 25 包；加 5 个基础组件，合计检查 30 包。其余 34 个已加载插件被标为本地。当前作者包 `sources.json` 的 70 条记录均为 Local；发布器把“随包内置”改写成“本地来源”，个人覆盖才恢复了部分商店身份。这是旧实现的内部计数，新的玩家文案按第六节统一为模组。

本次再核对的更新链路缺口：

- `BatchFindSources`／`ModSources.Exact` 确有自动匹配能力，但入口仅处理 Pending，旧 Local 被排除；手动／自动 `CheckAsync` 本身没有先补齐来源的完整阶段。
- `OverviewCatalogue.Create`、`ModSources.Apply` 和手动地址入口有仅凭字段／路径格式合法就设置 `SourceConfirmed` 的路径，确认规则尚未统一。
- `CheckProgress.Summary` 把接口去重数量、模组数量、基础组件和成功失败混合展示；`RunChecks` 还追加另一份基础组件摘要。
- 当前应重构识别、核验、调度、统计模型和展示整条链，而非只改结果字符串或给旧 Local 增加手工入口。

## 三、统一生命周期原则

1. **按实际需求工作**：主菜单无玩家／HUD／显示目标时休眠；机场已有玩家和语音时正常工作。
2. 场景、角色、HUD 创建销毁和设置变化作为主要唤醒信号；缺少稳定事件时使用有间隔的兜底重试。
3. 同一对象同一用途只保留一个等待任务；换场景、目标销毁或关闭功能时取消旧任务，并拒绝旧代次结果。
4. 查不到对象的结果也有有效期，防止“缓存为空”变成“每帧全场找”。
5. UI 数据读取、业务安全检查和绘制分层。耗时纯数据／文件解析放后台；Unity 对象访问和 UI 修改留主线程。
6. 优化显示缓存不降低安装、卸载、更新、依赖保护和事务提交时的实时核查标准。
7. 不以统一限制所有模组 Update 频率实现优化，各工程只裁剪自己的无效工作。

## 四、自研模组的具体修改

### A. 复活传送

主要文件：`汉化/BetterReviveTeleport/peaklg/reviveKey.cs`。

- 保留 `DeathTimerSync.Tick` 原有轻量守卫和通信时序。
- 在没有角色且无有效操作需求时提前退出，避免先查提示音对象。
- `PlayerConnectionLog` 改为需要播放提示音时按需获取，并缓存结果；失效后有界重试，场景改变清缓存。
- 提示音对象尚未就绪时，复活／传送的原有逻辑和文字反馈照常工作。
- 局内仍按原有角色名单、目标选择、二次确认和落点校验工作。现阶段不改幽灵过滤、玩家在场计时、RPC、重连记录或主客机权限。

验收：主菜单稳态全场查找次数为 0；机场首次按键、切换玩家、提示音、H／Alt+H／Shift+H、主客机、倒地与死亡、自传和飞行保护全部回归。

### B. 麦克风指示器

主要文件：`Better_MicIndicator/MicUIManager.cs`。

- 为 HUD 等待保存唯一协程句柄及场景代次，替换“每次 sceneLoaded 再加一条”。
- `Pretitle`／`Title` 无 HUD 需求时不启动等待；进入有 HUD 的场景再唤醒。
- 目标就绪前按低频间隔重试（初始建议 0.25～0.5 秒）；成功后结束等待。加载较慢时保持低频可恢复，不设置会永久丢失图标的僵硬超时。
- 换场景、管理器销毁、指示器关闭时取消该等待；重新开启时按当前场景恢复。
- 创建 UI 幂等：正确 HUD 上已有有效图标则直接复用，重建只处理本模组对象。
- M 静音、Alt+M 显隐和图标启用状态分开。保留轻量输入监听、原 dBFS／快攻慢放／PTT 门控及四档阈值。
- 配置回调只发布状态变化，Unity UI 操作统一回主线程。

验收：任意时刻等待协程不超过 1；主菜单稳态 HUD 搜索为 0；连续场景往返不累积等待或图标；机场和关卡的显隐、静音、音量与配置即时反馈保持正常。

### C. 更好的玩家距离

主要文件：`Plugin.cs`、`OverlayManager.cs`、`DownedManager.cs`、`Tracking.cs`。

- 以真实角色、调试目标和仍需显示的死亡标记为工作需求；无目标时跳过显示维护和主相机探测。
- 保留原有角色生成／销毁注册及场景切换后的必要一次补扫，处理 Awake 与 sceneLoaded 的先后顺序。
- 去掉每帧 `_activeLabels.Keys.ToList()`；使用可复用缓冲区，空列表直接返回。
- 相机缓存继续处理销毁／禁用／切换；只有存在显示需求才启用现有兜底探测。
- 字体重试在需要绘制或用户主动调试时执行，成功后停止；场景切换或必要设置改变才失效。
- 清理、淡出和兼容模式字号恢复在退出／状态变化时完成，避免提前返回留下旧名牌。
- 保留游戏米换算、近处让位、兼容模式、TimeTheme、皇冠／语音图标、死亡标记时长和假人调试。

验收：纯主菜单无目标时，相机搜索和标签更新为 0；机场出现玩家后自动恢复；重连、观战换相机、远近切换、昼夜变化、倒地／死亡和调试假人回归。

## 五、MCE 概览性能重构

### M1. 提示框：移动只改位置

涉及 `OverviewListView.cs`、`OverviewDependencyHints*.cs`、`SharedRelationshipSnapshot.cs`、`ComponentRelationshipTree.cs`。

- 分离提示内容生成、尺寸测量和位置更新。文本／宽度／字体／语言不变时复用尺寸。
- 普通鼠标悬停增加约 150ms 的停留触发；短暂划过、离开或目标变化时取消。键盘／手柄明确聚焦即时显示。
- 同一目标重复进入不重复建立内容；目标移除、滚动回收、弹窗遮挡时清除旧提示状态。
- 在数据代次改变时一次构建正反向邻接索引；悬停不再遍历整张图做分组，不再每次拼接全模组长签名。
- 按模组／组件身份、图代次、方案状态、语言、字体、宽度和展示选项缓存提示；旧代次整体释放或使用有上限缓存。
- 遮罩／画布边界和坐标缓冲区复用，屏幕尺寸改变时才重新测量；保留跟随／固定提示、两层摘要、完整依赖页及富文本换行。
- 显示关系图仍与用于卸载保护的后端图分离。

验收：同一提示静止或仅移动鼠标时，文本测量和关系索引重建计数不增长；快速划过未达到停留时间的条目不做昂贵内容生成；焦点与固定提示行为正常。

### M2. 静态控件：变化时更新

涉及 `MceTextWeight.cs`、`OverviewUi.cs`、`ProfilePendingMarkers.cs`、`UiActionStyle.cs` 等。

- 字体／子网格、按钮尺寸、主题、交互状态、待保存／应用标记改成事件或脏标记驱动。
- 以页面级刷新队列合并更新，减少逐文字／逐按钮的永久 LateUpdate。
- TMP 回调只标脏，统一在安全阶段处理材质和子网格，防止渲染回调递归。
- 正在播放的悬停／展开动画照常逐帧更新，静止后退出；必要兜底检查集中且低频。
- 非当前标签页停止自己的展示维护。保留共享数据结果，不在隐藏标签页重建控件。

验收：静止列表的控件维护量随实际变化而不是总条目数增长；中英文、回退字体、主题、禁用态和各色标记保持一致。

### M3. 行复用与可视范围渲染

涉及 `OverviewListView*.cs`、`OverviewCascade.cs`、列表交互和行绑定代码。

- 用完整视图模型维护顺序、分组、筛选、选择和逻辑高度；绘制只租用可见行及少量上下缓冲行。
- 普通模组、分组标题、基础组件分别建控件池，按需要增长并设置合理回收上限。
- 对象回池统一解绑按钮、悬停、手柄、配置等监听，清空旧绑定，防止复用后操作到另一模组。
- 版本／标记／状态变化局部更新，结构变化才重新布局；避免 Clear＋Destroy 全表重建。
- 数据身份采用稳定行键，能区分重复 GUID、不同安装包和基础组件位置。业务操作始终针对数据身份。
- Shift 范围选择、拖动跨屏、自动滚动、排序、分组折叠、搜索与手柄导航按完整数据模型计算；不可见焦点项先滚入并绑定。
- 所有条目仍参与导出、更新、来源核查和依赖判断；控件池只限制绘制。
- 合并同轮数据完成通知，取消更新完成回调与共享缓存回调导致的第二次重建。
- 全局 Canvas 强制刷新退出常规路径，必要首帧布局也只做一次并记录成本。

验收：用 60／120／300 条目样例验证，活跃行对象数由视口决定；更新同一结果不会再次重建；连续滚动、打开关闭页面、语言与方案切换后对象和监听数量稳定。

### M4. 队列读取与后台快照

涉及 `OverviewUpdateQueue.cs`、`OverviewPage.Updates.cs`、相关快照与助手发布逻辑。

- 比较文件指纹／业务 revision，未变化时复用解析结果；JSON 解析放后台。
- 指纹覆盖 queue、shop task、worker error 以及有关事务记录，独立事务状态变化仍能被观察到。
- 首先核对助手是否无业务变化仍重写完整快照；若有，改为状态变化才发布完整快照，必要心跳保持轻量。
- 主线程只接收不可变结果并更新实际变化的控件，错误和进度合并展示。
- 后台结果绑定根目录／环境／代次，关闭页面或切换环境后旧结果作废。
- 异常读取保留最近有效视图，显示错误，并沿用危险操作的安全阻断。
- 更新泵仅合并同类展示刷新；业务回调逐项保留，按预算处理，不丢提交、取消、结果或错误。

验收：文件内容与相关事务状态稳定时，首次读取后 60 秒内不重复解析；各相关文件单独变化都能刷新；旧环境结果不会覆盖当前视图。

## 六、MCE 来源识别与更新检查深度重构（主线二）

本节取代前版“来源分类＋多类统计清单”方案。修改的是 MCE 的管理能力，第三方模组本身仍按第一节保持原样。

### U1. 来源确认统一为雷霆商店身份

将四件事独立保存和判断：

| 信息 | 用途 |
|---|---|
| 项目主页 | GitHub／Codeberg 等开发主页、说明和检索线索 |
| 雷霆商店来源 | 真实 Thunderstore 模组页面及其对应的官方目录／API 身份 |
| 分发方式 | 随包内置、依赖下载或本地导入 |
| 用户策略／文件归属 | 是否允许检查／更新，以及安装卸载所需的独立所有权证据 |

- **只有核验到对应雷霆商店模组页面／真实身份，才成为“商店来源已确认”。** 官方目录的有效缓存可作为核验依据，无需每次显示 UI 都联网。
- GitHub／Codeberg 地址保留为项目主页，同时继续尝试匹配雷霆商店；仅找到项目主页时，商店来源仍未确认。
- Namespace／Name、Team-Name 文件夹、输入的 URL 先作为线索；单纯格式合法不直接设置已确认。手动填地址、单个查源、批量查源、自动检查共用一个确认器。
- 来源身份状态与本次网络结果分开：短暂断网不抹掉既有有效身份；本次查询失败也不写成“已是最新”。
- 显式“本地自用／不自动匹配”是独立用户选择。磁盘安装位置和内置导出都不自动产生该选择。
- 已确认更新来源只用于元数据查询和后续用户操作；文件归属及安装卸载安全检查仍走原来的独立规则。

### U2. 全局检查自动包含查源阶段

统一流水线：

```text
获取本轮完整模组清单与现有分组
→ 读取用户策略和有效来源缓存
→ 对缺少商店来源的模组自动生成候选
→ 核验真实雷霆商店身份
→ 查询版本并与可信本地版本比较
→ 回填模组状态、小绿点和进度
→ 输出简短总结
```

候选线索按可信度处理：既有已核验安装记录／来源证据、明确雷霆地址、清单中的身份、规范目录、原始模组名和项目主页对应关系。展示译名只用于展示。

- 唯一且证据一致的真实商店匹配自动确认；重名、不同作者、分支或证据冲突保留候选，用户需要处理时再选择。
- 模糊名字命中用于推荐，不仅凭相似分数认领来源；同目录的不同模组也不自动共享一个身份。
- 没有匹配、只有 GitHub 主页、需要裁决的项目保留明确状态，并继续本轮其他模组；不反复弹窗打断自动检查。
- 现有“批量查找缺失来源”成为同一识别器的主动重新匹配入口，不再维护一套与更新检查脱节的规则。
- 主菜单／机场自动检查仍沿用既有调度和许可；来源匹配不会自动下载 DLL 或安装更新。

### U3. 旧 Local 记录重新纳入自动识别

- 读取兼容层识别旧内置发布记录，把历史 Local 重新送入来源核验流程，解决只处理 Pending 导致永远跳过的问题。
- 原记录中的商店 ID、清单、既有核验和项目主页都用于恢复；唯一可靠匹配自动恢复，只有歧义／冲突留给用户，不要求重新手填全部来源。
- 旧记录无法区分发布器改写和明确手动意图时保留候选，不擅自覆盖选择；本机明确的 Local／停止自动匹配设置继续优先。
- 新记录区分自动识别结果、发布信息和用户明确选择，避免再次丢失来源意图。
- 自动结果写入按当前环境和安装实例隔离的派生缓存；用户覆盖单独保存。同 GUID 的不同安装／不同整合包不会无条件套用旧确认。
- 签名作者包和已保存库存原件保持；本轮开发仅用沙盒副本验证，真实来源文件不在本轮直接批量修改。

### U4. 导出与导入保持来源身份

重点：`PackPublisher`、`ModSources.Export` 及 `Updater/PackImports` 的消费逻辑。

- 删除“IsInline 就强制写 Local”的规则。已核验商店身份、主页和已知版本在本地完整导出后原样保持。
- 真正本地自用、未确认和有歧义的状态如实保留；GitHub 地址不在导出时升级成商店身份。
- 内置／下载由实际内容清单与依赖计划表达；完整载荷已存在时直接使用已有文件，离线导入不因保留商店身份而重复下载。
- 缺失内容走原预览与下载同意。当前安装、版本身份与精确文件归属仍各自校验。
- 来源可确认但本地比较版本缺失时，在对应模组状态里说明；保留已知版本，不把不同口径的程序集版本强行当作商店版本比较。

### U5. 玩家界面统一叫“模组”，只显示进度与总结

**默认检查结果移除“资源包／插件／基础组件／成功包／失败包”的并列表，不再另造一套分类。** 原有基础分组若本来就在概览中，按该现有分组参与，不另外输出类型计数。

运行中最多显示现有分组进度，分组名称、颜色和顺序沿用当前概览：

```text
{现有分组名称}：检查更新 {n}/{N}
```

总体进度：

```text
正在检查更新 {n}/{N}
```

正常结束固定为：

```text
共检查了 {n}/{N} 个模组，检查出 {K} 个可更新模组。
```

- 结果区不逐项罗列哪些模组需要更新，不新增重复的“可更新名单”。具体对象由现有小绿点指示，用户主动打开的版本／更新队列详情保留。
- 手动检查、自动检查、状态栏、来源下拉及悬停摘要共用这套格式；去掉 `RunChecks` 额外拼接的基础组件摘要。
- **N 按本轮清单中的模组条目计数**，与概览使用同一单位。全局检查使用完整清单，不受分组折叠、视觉筛选或虚拟化可见行影响；本轮范围固定。
- n 是已经得到检查流程结果的条目数，每条仅完成一次；查源和查版本是同一模组的处理阶段，不重复加数。
- 本地自用、未匹配、需确认、许可关闭和查询失败保留各自结果，在原有模组状态／来源入口按需查看；这些结果不会显示为“已是最新”。
- 取消或整体故障保留真实进度并使用相应的短状态提示，不将尚未处理的条目补成完成；单项失败保留原因。
- K 按本轮有效结果中带可更新标记的不同模组条目计数。同一行名称和版本两处绿点只算一个条目。
- 多个模组条目指向同一商店身份时，后台只发一份版本请求，完成后分别更新相关条目、分组进度和角标。接口请求数只进开发诊断。
- 绿色角标与 K 共用同一份有效结果快照；缓存带核验时间，过期／失败结果不冒充本轮成功查询。

### U6. 识别与检查的性能架构

逻辑拆分为来源发现、身份核验、版本查询、结果模型和界面展示，由统一检查协调器管理。

- 手动、自动、批量查源共用去重和取消机制；同环境正在运行的任务复用或明确替换，避免并发跑两套检查。
- 商店目录共享现有缓存，按目录代次一次建立身份、原名和项目主页索引。每个模组查索引，不重复扫描完整商店目录、做同样的正则规范化。
- 来源结果按安装实例／文件戳／当前环境／用户选择代次失效；无匹配也短期缓存，目录变化或主动重新识别后重试。
- 主线程只抓已加载插件的不可变元数据，后台处理静态清单、索引和网络；Unity 对象及 UI 留主线程。
- 模组扫描只读取证。移除扫描过程中逐个同步写个人来源文件的副作用；自动核验缓存批量提交，用户明确选择单独提交。
- 延续有上限的网络并发、超时和取消；每个身份去重查询，进度按模组条目回填。
- 界面进度合并刷新（建议 100～200ms 一次，仅有变化时），不为每个 HTTP 完成事件重建整表；结果阶段只更新受影响的行。
- 所有完成回调校验任务／环境代次；旧任务不得覆盖新来源、覆盖另一整合包或重复增加计数。

重点串接文件：`OverviewCatalogue.cs`、`ModSources.cs`、`SourceUi.cs`、`OverviewPage.SourceTools.cs`、`OverviewListView.EditControls.cs`、`ThunderstoreUpdateService.cs`、`AutomaticUpdateChecks.cs`、`OverviewListView.cs`、`PackPublisher.cs`、`Updater/PackImports.cs`，以及对应语言词条和测试。

### U6a. 会话最后补充的匹配算法约束

- 严格名称只忽略大小写与分隔符；分词保留 Fix/Fork/CN/Plus 等分支语义。
- 精确官方身份、可信既有映射优先。名称唯一仍须可信作者或完整项目仓库等交叉证据；同仓库多个分支保持歧义。
- 编辑距离和分词重合结合作者、完整仓库与版本线索，只用于可解释的候选排序；任何相似度或领先分差均不单独授予自动确认。
- 官方结构化目录/API同时检查身份、有效版本、社区与废弃/停用状态；通用基础组件仅走明确允许路径。GitHub/Codeberg始终只是项目主页与对应证据。
- 用户手选映射记住选择，安装实例或证据冲突时复核；未知GUID不假设可以在雷霆目录直接搜索。

### U7. 专项验收

| 场景 | 期望 |
|---|---|
| 仅有 GitHub／Codeberg 主页 | 商店来源仍未确认，参与自动匹配 |
| 格式合法但商店不存在的 ID／地址 | 不标已确认，保留实际核验结果 |
| 唯一可靠的商店身份 | 自动确认并继续检查版本，生成规范商店地址 |
| 同名多作者、分支或身份冲突 | 给出候选而非误绑，其他模组继续检查 |
| 用户明确本地自用 | 选择保持，自动识别不覆盖 |
| 旧导出造成的 Local | 重新核验，可靠匹配自动恢复；原作者文件保持 |
| 商店来源模组本地导出再导入 | 来源和版本信息保持，完整内置内容离线可用 |
| 多条目共用商店身份 | 单次请求，按条目更新各分组进度和绿点 |
| 分组折叠／筛选／滚动 | 全局检查范围和分母不变 |
| 缺本地比较版本、404、超时、取消 | 状态真实，不显示假“最新”或假完成 |
| 自动和手动同时触发、途中切包／改来源 | 任务去重，旧结果隔离，条目只计一次 |
| 简中／繁中／英文结果文案 | 统一使用模组／mods，仅进度和简短总结，无重复更新名单 |

验收必须同时覆盖自动识别、来源保持、版本比较、完整进度和简洁展示；只替换 Summary 文案不算完成本主线。

## 七、UBImGui → LocalFix 的条件方案

### 先作决定，再纳入发行

当前约 0.15ms/帧，列第二梯队。先完成自研后台空转优化，再在相同环境测量 UBImGui 的输入、NewFrame、Render 和 Layout 订阅者，业务订阅者耗时另列。

执行用的“值得纳入”判据，满足一项后再验证候选收益：

1. 无窗口时持续 CPU 平均成本达到约 **0.3ms/帧**；或
2. 有效分配计数显示热路径持续产生约 **16KiB/帧或 2MiB/秒以上**可消除分配；或
3. 出现可重复、定位到该库的 **5ms 以上尖峰**，候选补丁能稳定改善该项。

每种条件至少三轮同条件比较，同时核对输入、窗口、焦点和渲染行为。没有达到纳入标准时，本轮记录结果并保留原库。

### 纳入后的实现边界

- 在 LocalFix 新增独立配置分区、独立 Harmony owner 和启动状态说明。
- 可复用现有研究，但重新按 LocalFix 的可选依赖方式接入；缺依赖时无类型加载错误，不强制安装 UBImGui／ImGui.NET。
- 第一层优先做等价优化：缓存原版键值映射，保持枚举别名／映射碰撞顺序；复用等待对象和缓冲区；没有几何内容时跳过上传／绘制。
- 输入差分需在焦点切换、窗口唤醒、上下文改变时完整同步，验证松键、鼠标按钮、滚轮、中文输入和光标所有权。
- 休眠只用于已明确确认无需求的调用方。未知旧 Layout 订阅者继续原循环；不通过粗暴停掉整个 ImGuiBehaviour 实现。
- 不为接入休眠另改第三方调用方 DLL。需要额外接口改造时，单独列出，不混入本轮必做项。
- 发生挂载或运行兼容问题时，只撤回本分区，节流记录原因并恢复原库；其他 LocalFix 修复继续生效。
- 原生 cimgui、渲染 ABI、地形／存档／联机逻辑保持。

## 八、实施顺序与协作边界

1. **基线与快照**：记录实际源码／现装版本、安装位置、当前未完成改造；完整快照包含未跟踪源码。建立每组独立变更清单。
2. **三项后台优化**：复活传送、麦克风、玩家距离分别实现、单独回归；先消除主菜单稳定负担。
3. **MCE 来源与结果模型**：先建立统一自动查源／商店核验／版本检查协调器和按模组计数的结果模型，完成旧记录兼容、导出来源保持及简洁文案。
4. **MCE 低风险热路径**：在统一结果模型上接提示／关系缓存、队列快照、合并刷新和控件脏标记。
5. **MCE 行池与虚拟化**：稳定后实现，单独验收交互，并与新检查进度、来源结果和角标联动回归。
6. **UBImGui 决策**：复测、判定；通过后才实现／保留 LocalFix 可选候选。
7. **综合回归与候选交付**：按下表实测，最后处理版本、文档、完整包和部署。

即使并行开发，各工程互不覆盖；MCE 共享文件由同一集成人串行合并。单项失败只回退该项的已确认变更，不重置整个工作树。

### 当前 MCE 的特殊发行边界

当前源码另有导入／目录整理／Framework 4.8 助手改造，功能剩余项见 `../InstallationFlowChecks/实施状态.md`。实施时核对最新实际交付为 `../DropdownSuffixChecks/deployment_20261030_170457/result.json` 的完整37文件（含Framework助手及WPF窗口）；旧文档中的“现装23文件／轻量助手未部署”为历史状态。

本计划不推进那批未完成需求，也不回退或覆盖它们。性能与来源重构分别保存变更清单；涉及共享导入／发布接口时只做本方案所需的来源与分发契约兼容，不并入额外目录整理或助手 UI 需求。打包前核对可验证的发行基线和完整助手协议；没有明确一致的发行基线时停留在项目候选验证，不用单换主 DLL 的方式混配助手。

## 九、验收方法与通过条件

### 性能场景

使用相同模组、整合包、分辨率、画质和帧率设置，启动稳定后测试；每段 60 秒，至少三轮。冷启动／首次打开另记，不混入稳定段。

| 场景 | 核对重点 |
|---|---|
| Title 主菜单静止 | 三个自研局内模组的搜索、等待、相机探测和分配 |
| 原生设置静止 | 同一环境参考基线 |
| MCE 概览静止 | 逐帧组件、队列解析、提示／布局空闲工作 |
| MCE 快速划过名称／版本／按钮 | 提示触发、测量、关系索引、输入响应、帧时间 |
| MCE 连续滚动、搜索、折叠 | 行池规模、复用绑定、滚动／选择／手柄 |
| 自动查源／旧 Local／仅 GitHub／歧义来源 | 商店核验、缓存、用户选择与本地导出往返 |
| 手动／自动检查与结束 | 现有分组 n/N、简短总结、绿点一致性、去重和主线程尖峰 |
| 机场与关卡、离房回主菜单 | 唤醒、取消、缓存失效、真实功能回归 |
| UBImGui 无窗口／有窗口 | 条件项的 CPU、分配、输入与渲染对照 |

### 指标与计数器

- 整帧：平均帧时间、p50／p95／p99、>16.67ms 和 >50ms 次数、GC 次数与暂停时间。
- 自研后台：全局查找数、HUD 搜索数／等待数、相机探测数、标签维护数。
- MCE：提示内容生成／测量数、关系图构建数、活跃行对象数、结构刷新数、队列解析数、缓存失效数；另记商店目录加载／索引构建、来源匹配、接口请求、检查批次和进度发布次数。接口去重计数仅供开发诊断。
- 计数器只在测试模式启用并按窗口汇总；不逐帧写文件或打印日志。
- 分配计数可用时记录 bytes；运行时缺该计数时记录 GC／内存趋势并做单项对照。FrameDoctor 方法插桩版与仅宏观版分开跑，不通过开启高风险看门狗取证。

### 必须满足

1. 主菜单无目标稳态：复活提示音全局搜索、麦克风 HUD 搜索、玩家距离相机探测均为 0；HUD 等待不累积。
2. 三项后台模组主菜单自身热路径合计平均目标 ≤0.10ms/帧；完整帧时间和 GC 结果另表保留。
3. 同提示仅移动鼠标时不重复测量；同一数据代次不反复建立关系索引。
4. 行对象随视口规模增长，不随全部条目线性常驻；监听和对象数量经反复开关／滚动后稳定。
5. 一次更新结果最多触发一次必要结构刷新；通常只改对应状态；不再出现重复全表重建。
6. 相关文件稳定时不重复解析；相关状态真实变化、出错、取消和环境切换均正确反馈。
7. 英文／简中／繁中、不同缩放、长名称、重复 GUID、基础组件、键鼠／手柄和拖动范围选择通过。
8. 自动查源只以真实雷霆商店身份确认为完成匹配；仅项目主页、歧义、无效 ID、旧 Local、显式本地及失败／取消分别通过专项回归。
9. 来源的发布→离线导入→检查往返正确，用户选择、许可、依赖和归属保护保持；现有分组进度与简短总结按模组条目计数，K 与绿点结果一致，结果区不重复列更新名单。

实机交互出现名牌错误、按键失灵、提示串行、错操作对象、旧状态覆盖、重复任务或数据变化时，先修回归再讨论性能通过。

## 十、构建、部署与回滚

- 实施前按工程规则确认修改范围；构建和验证统一关闭自动部署（沿用 `EnableDeployment=false` 等实际开关）。
