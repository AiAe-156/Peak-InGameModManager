# MCE 性能收尾独立审查（2026-10-30）

## 边界与结论

本轮仅接续性能线，不改来源线文件、不部署、不启停游戏、不改真实配置/库存/队列/来源数据、不改总 README/CHANGELOG。保留此前全部改动。改前快照：`备份/20261030_MCE性能收尾/`。

**结论：安全缺口已有源码修复、离线检查通过；M1–M4 不能标记全部完成，尤其 M3 仍是 row shell 池，不是完整子控件池。未做实机验收，不能据此宣称性能或交互全部通过。**

## 本轮修复

- 垂直导航不再只连已绑定控件：按完整 `_virtualRows` 模型查下一行、滚入视口、创建显示租约、选择可交互控件。保留横向显式导航。焦点变化使可见范围重算，上一屏焦点不会不断钉住旧行。
- 结构刷新按稳定行键和控件列捕获/恢复焦点；局部更新也恢复焦点。若条目被筛除或控件不可交互，不强行恢复无效目标。
- 作者跨屏拖动继续钉住数据身份；普通模式原生 ScrollRect 拖动也钉住事件源，结束时使范围失效，防止滚动中销毁事件目标。自动滚动后及时绑定新范围。
- 回收明确清空新导航/拖动钩子，继续清空行交互、点击、普通悬停、焦点、按钮、Toggle 与依赖提示绑定；失效租约早于解绑。子对象先停用再 deferred Destroy，不把不透明监听重定向到其他身份。
- 普通提示测量键补字号，聚焦可即时显示。现有文本/宽度/字体/语言未变化时移动仅定位。
- 检查进度改线程安全最新值槽，150ms 发布一次、相同内容不重复发布，不为每个进度事件入 Unity 更新队列。业务完成回调仍逐项保留。
- `RunChecks` 删除额外 `InfrastructurePackages.Summary()`；预 await 库存等纯数据工作放 Task.Run，主线程先捕获模组清单/整合包/环境上下文；完成和错误拒绝旧环境，关闭/切环境取消并清空进度。
- 更新完成与 CacheRevision 使用相同显示签名；通常仅重绑显示状态变化的行，不 Clear/Destroy 整表。标签/来源过滤影响结构时才 Render。组件按自身结果签名刷新；来源状态进入签名以避免遗漏变化。可见变化行仍重建子控件，**不是叶级状态 patch**。
