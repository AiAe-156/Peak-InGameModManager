## 问题与优先级

### P1 批次统计不是完整审计，阅读结果还会改变结果
- PendingMods有Apply副作用；BatchResults再次Apply并重算counts；刷新目录/个人修改后结果可能漂移，缺少本轮before/after。
- 手动返回使用旧mods闭包；同GUID跨包可能统计重复，没有插件行/物理包的明确单位。

### P1 来源身份与更新可用性混为一谈
- StoreIdentityIndex.cs:15把Deprecated条目从_identity/_names/_search全删；因此Identity、Confirm、候选、原因都无法说明“已知来源但弃用”。
- ModSources.Reasons.cs:13也排除Deprecated，导致确有同原包名却提示不存在。
- ThunderstoreUpdateService.cs:262以后把弃用转精确API请求，最终报没有active latest。来源应保留，更新单列不可用，不改成Pending/Local、不自动换fork。

### P1 旧线索与权威证据混在相同字段
- ModSources.Get按GUID把个人或多个发布sources合为一条；Apply:88写SourceNamespace/Name，Index.Resolve:28只要身份不存在即return null。
- 发布hint/derived hint/明确manifest/用户指定都走同一入口。失效发布hint可以阻止当前高置信匹配；重置自动选择仍从Get捡回发布hint。
- 需要“事实/个人政策/猜测”独立，绝不能通过清空整个sources修复。

### P1 商店回执和用户本地策略优先级需有明确时序
- 当前Apply开头TryInstalledStore强制优先；之后用户再点“标记本地”Set会写记录但Apply立刻恢复Store，UI动作静默无效。
- 当前用户要求商店装成功直接确认，应禁止该类条目的本地动作并说明，或定义之后明确用户覆盖时序；不能两种规则并行冲突。建议本阶段禁止成功回执项“标记本地”，给“此包已由商店安装，来源已确认”；保留现有历史个人记录不删除。

### P2 批量刷新快照不一致与缺少请求身份
- BatchFindSources先Catalog(false)再Discover(force=true)内部强刷，结果窗口用第一次目录。手动retry还有第三次Catalog；候选与实际判定可能不同。
- 要一个catalog revision、一轮before/after、一份decision结果；环境/choice/installation token变化取消，不允许迟到结果写新环境。
- SourceUi.AutoIdentify用CancellationToken.None，不能随页面/环境生命周期取消；改传操作lifetime与context。

### P2 判断分散与性能
- Resolve/Reason/UnresolvedReason分别实现事实与原因，后者只有笼统字符串。
- RepositoryBranches对每个candidate全目录再遍历，fuzzy最坏平方；构造索引时预计算repository -> identities数量、author索引。
- TryInstalledStore作为查询会写mod；ExplicitLocal也调用它，查询函数改变状态。分离纯receipt lookup与统一Apply。

### P2 导出不是纯读取
- Export每行Apply会重写传入live行，发布中可能处于异步线程。且来源记录以GUID为key，同GUID不同包可能互相覆盖。
- 要导出冻结decision投影；相同GUID多个不同来源不得静默后者覆盖，报告歧义并要求发布选择。embedded只代表分发方式。

## 细化实施方案与文件边界

### A 来源决策内核（主线程先做）
新增SourceDecision.cs：
- SourceOrigin枚举 PersonalLocal/PersonalStore/InstalledReceipt/Manifest/PublishedHint/DerivedHint/AutoMatch。
- SourceReason枚举 ReceiptVerified/ManualConfirmed/ExactUnique/AuthorSimilar/Deprecated/NoCatalogEntry/PublisherConflict/RepositoryConflict/Ambiguous/LocalChoice/CatalogUnavailable。
- SourceDecision不可变：row key(Guid+PackageRoot+Location)、Kind、Namespace/Name、InstalledVersion、Origin、Reason、CatalogRevision、Deprecated、CanAutoUpdate、候选证据/分数。
- SourceEvidence快照保留原始manifest/包名/作者和个人政策，不使用译名，包含有效安装回执。
- Evaluate(evidence,catalogSnapshot)纯函数；Apply只把decision投影live行；Explain/候选/来源报告都读decision。
- 个人Local兼容个人runtime旧记录，按环境/包目录，不从published导入个人policy；商店成功receipt直接确认。
- identity lookup含弃用，自动名称候选默认优先active，不把弃用当不存在；弃用明确identity保留，并关闭自动最新版更新。
- 明确manifest/manual冲突保护；失效published/derived只是hint，不能阻断其他独立强证据。
- 预建author/name/repo索引，fuzzy >=.90且领先>=.08，可信作者/仓库冲突继续拒绝。
涉及ModSources*.cs、StoreIdentityIndex.cs、ThunderstoreUpdateService.cs；保留外部调用包装，先测试再接UI。

### B 批次与展示（A稳定后主线程做）
新增SourceIdentificationBatch不可变结果：Environment/CatalogRevision、AllRows、Before/After、NewlyIdentified、PreviouslyIdentified、StillPending、LocalSkipped、DeprecatedKnown、Failure/Cancelled。
- 开始先capture全部行before，再统一Evaluate，pending只决定网络工作范围，不影响总数。
- 摘要写“当前商店已确认 X（本轮新增 Y）｜待定 Z｜本地 L”；同一行唯一计数；列行与统计保持守恒。
- BatchResults不调用Apply；手动动作生成更新后的批次结果，不拿旧闭包盲重算。
- 可见行译名优先，原名/实际包名/版本，精确原因：商店无此身份/只有别的发布者/原来源已弃用/冲突/离线，不再“没找到”一刀切。
- 所有批量/保存检查/重置入口使用同一service和一次catalog；加生命周期取消、请求代次、single-flight；不隐式保存配置草稿。
涉及OverviewPage.SourceTools.cs、OverviewListView.SourceRetry.cs、SourceUi*.cs、ConfigurationIssueReport.cs。

### C 回执/导出一致性（A后执行，与B文件边界分开）
- TryInstalledStore改纯ReadInstalledIdentity，接现有成功ledger（非下载队列），自身payload/路径匹配，明确证据冲突；空字段/损坏JSON返回可解释失败。
- 本地按钮按decision能力禁用，不能点击后无效果。其他来源动作不影响安装文件所有权。
- Export接冻结decision列表，不Apply live mods；个人policy/指纹不导出，kind与distribution分开；相同GUID来源冲突停止该项并报告。
- 读新导出sources再接收端Evaluate验证store/local/pending/embedded语义。
涉及ModSources.Installed.cs、ModSources.Export独立文件、PackPublisher.cs；UI按钮能力由B读结果。

### D 独立验证（tester只读/隔离测试；若代理仍失败主线程执行并说明）
- 现有IdentityMatchChecks/InstalledSourceChecks补fixture与多轮刷新，不替换断言去掩盖行为。

- 真实数据read-only生成脱敏快照，用Mono.Cecil读取BepInPlugin元数据+manifest+当前published/personal/catalog/ledger，不load DLL、不写真实来源。
- 对截图六项逐条产decision/reason，不强行让无包条目“匹配成功”。
- 关键断言：before/after统计守恒、0新增可同时有N已确认、同catalog一致、决策查询无副作用、导出不改变输入、商店成功来源不丢、用户Local不串环境、弃用不抹身份、旧hint不压手选。
