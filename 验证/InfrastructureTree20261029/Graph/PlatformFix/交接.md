# Platform reference 定点修复交接

## 结果

独立 PlatformFix 工程链接实际 production collector/graph，30 项检查通过。没有构建主工程或原 Graph 工程，没有修改原 Graph/Program.cs；没有部署，没有扫描真实全模组，没有写真实 Managed/core/config/库存/队列。

## production 变更

仅修改 `src/Updating/ComponentDependencyCollector.cs`。

- 删除按 System/UnityEngine/Assembly-CSharp 名称前缀直接放行的平台白名单。
- root 名为 BepInEx 时平台路径为其 parent/PEAK_Data/Managed；否则 root/PEAK_Data/Managed。
- 先搜索已安装 core/patchers/plugins 中的真实同名 provider（包括 dll.old、多 provider）。即便 provider 身份与平台不一致，也保守保留对这些真实组件的硬边，不准回退平台绕开保护。
- 仅在无安装 provider 时按需读 Managed/<reference.Name>.dll。Cecil metadata 只读，不 Load、不执行、不解析第三方类型；不遍历游戏全部 DLL。
- 精确核对 metadata name（忽略大小写）、public key token、Version；token 空值同样参与比较。不采用运行时 binding redirect/版本兼容推测。
- 路径型名字、链接目录/文件拒绝；不存在、损坏、身份不匹配保留 missing 硬边，证据携带具体原因/required/found identity。游戏平台 DLL 不创建可卸载组件节点。
- 缓存仅属于本次 Collect，保存候选身份而非第一次请求是否匹配，避免不同版本请求借缓存误通过。

## 接口

公开接口完全不变。仅私有 Metadata.Requirements tuple 从 `(Target, Kind, Hard)` 扩为 `(Target, Kind, Hard, AssemblyIdentity?)`；AssemblyIdentity 保存 name/version/token。ComponentDependencyGraph 未改，组件 Assemblies 名称列表保持原兼容行为。

## 保守失败策略（未削保护）

无 author/无法确认包身份的 manifest、无关损坏 metadata 仍进入 graph.Failures，导致未命中已知保护路径的卸载 unknown。原因：坏证据可能隐藏 MCE GUID 种子或额外硬依赖，当前没有可证明其与 MCE 闭包无关的可靠依据；直接吞掉或仅按当前已知闭包过滤会错误放行。已知 MCE→ModConfig→Core 仍给出保护路径，不被 unknown 覆盖。此次解决的是合法游戏引用被错误标 missing，不承诺所有混合/损坏真实环境均可卸载。
