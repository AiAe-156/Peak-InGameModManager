# 基础组件统一列表 UI（2.0.0，源码／测试，未部署）

## 实现

- 固定 Core/Patcher 组在普通可编辑分组之前；简中／繁中／英文组名、类型标签按本轮精确文本。未加入 OverviewMod、profile Mods、groupId 或导出目标，未伪造 GUID。
- 使用普通列表传入的 xEnable/xName/xSettings/xHome/xFolder/xVersion/xAuthor/xDescription 坐标、42 高基础行、版本20／名称19／作者18／简介16字号。齿轮灰置并说明无设置，home 为来源菜单，folder 同普通行；启用列明确“—”，没有启停控件。类型并入简介，窄屏／截断时名称和来源 tooltip 仍有类型、路径和保护原因。
- 默认紧凑单行。小箭头首次展开一层反向消费者（不是本身的依赖）；名称列内缩进／竖线／分支、名称与实际版本（未知明确标记）、证据与 hard/soft、cycle/shared/unknown/截断。逐层展开最大16层、24节点行预算，其他列始终顶行对齐。树节点只读，不继承模组选择／拖拽／卸载交互，无 hover scale。
- 主线程捕获 confirmed SourceKey→AssemblyPaths/Location，后台一次 Collect(root, graphconfirmed) 覆盖 core/patchers/plugins。行渲染只读图。inventory revision、generation、workspace+RevisionStateHash 拒绝过期完成；编辑／滚动／键盘选择期间延后异步重画；保留既有 Render 的滚动恢复。
- 保护组件名称右侧灰色 ⊘、名称/home tooltip 和来源菜单提供原因链；菜单卸载项 disabled，另有可点击“为什么不能卸载”全文说明，版本入口不因固定卸载闭包保护变灰。普通模组 SourceUi 菜单也显示保护理由，执行前重查。
- 非保护组件菜单卸载进入现有 ShopWindow，等待真实安装快照，核对仍为原包后发起既有预览。patcher 仍用现有 UninstallDialog；core 走 ShopWindow 原版官方旧 ZIP 同意→下载批准→文件预览→确认流程，不新造自动 confirm。修复原 task 刷新排除所有 uninstall 导致 core 流程不可见的接线；卸载版本取实际现装而非商店最新版本。
- ShopInstallationState 新增可选原因提供器，只约束卸载，不约束 CanInstall；ShopWindow 后台同时采集并发布图，详情显示具体原因而不是丢失解释。Graph/worker 无修改，执行保护仍独立兜底。
