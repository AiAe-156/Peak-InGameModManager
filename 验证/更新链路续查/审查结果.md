## 已运行复现（生产源码 + 隔离IO）
命令：dotnet run --project 验证/更新链路续查/AuditChecks -c Release。
日志：audit.log。结果目录：AuditChecks/bin/Release/net10.0/audit-85c9376b4bf542e1b647dbcdb849d3ad/results.json。

1. ResourceOperationDraft.Stage：真实accepted回执存在，尚未调用Count时仍抛等待回执，阻止新操作。ResourceOperationDraft.cs:54、62-65。清理accepted草稿仅发生Count getter，业务正确性依赖UI读属性顺序。
2. ResourceOperationDraft.Snapshot：同场景返回已被接受的旧操作；可令工具页/检查报告继续显示已提交操作。ResourceOperationDraft.cs:55-58。与第1条同根因，应统一Load/同步回执而非逐调用点补Count。
3. ShopQueueProjection：真实cancelled任务投影成preparing。ShopQueueProjection.cs:10的默认分支，未包含cancelled/停止状态映射；造成取消后仍像工作中。
4. WorkerResourceBatch.ControlResourceBatch：保存当前批次A，发送JobId=B的resource-cancel，A仍Completed=true。WorkerResourceBatch.cs:136-141/179-186没有校验批次ID；UpdateQueueView.cs:281实际发送空JobId，使旧行/延迟操作无从绑定。测试未修改生产队列。

## 源码确认的UI/翻译缺口
5. UpdateQueueView.cs:158-161/186-192：提交已发布但尚未accepted时仍统一draft/待保存，允许保存且提供移除；移除会被底层阻止。需要单独“已提交，等待确认”状态，未提交和确认中分开，不一概宣称未开始下载。
6. UpdateQueueView.cs:321起ShowDetails仅查询_snapshot.Jobs；draft行只放在Refresh局部列表，点击草稿详情直接返回。saved-resource虽在snapshot中，但只显示摘要和剩余数字，未显示Commands的模组/版本清单。应按显示行类型统一解析详情。
7. UpdateQueueView.cs:287只读取批次DependencyWarnings。WorkerResourceBatch.cs:153-156允许单操作卸载进入shop task警告分支；该路径batch.DependencyWarnings可为空，此时新队列入口提示“无待确认影响”，但真正警告还在shop任务里。管理Tools已有双分支，需共用而非复制半套。
8. WorkerResourceBatch.Error及snapshot.Error包含英文前缀Saved resource batch needs attention、Combined resource environment requires dependency impact confirmation before continuing、Combined dependency confirmation is required等；src/Loc.UpdaterTerms.cs及共享UpdateMessages词条均未覆盖这些原文/前缀。Loc.LocalizeMessage对这些复合消息不会逐行/前缀自动识别。需现有词表加入英文原文+简繁中文，保留具体包名路径/底层原因。
