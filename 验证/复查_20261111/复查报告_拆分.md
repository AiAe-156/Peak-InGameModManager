## 已检查没问题的方面

- **cfg**：`CopyConfig` 在所有 `Config.Bind` 之前；新 cfg 已存在时不覆盖。BepInEx 5 的 `BaseUnityPlugin` 实际上在构造时就建了 `ConfigFile`（`saveOnInit=false`，当时文件不存在，没有读也没有写），所以注释里的「懒建」说法不准，但不影响结果：`Reload()` 会把复制来的全部行读进 `OrphanedEntries`，之后 `Bind` 从里面取值，效果正确。旧 cfg 里已删除的键（如 2.3.12 的 `Classic brown colours`）留在 orphan 里，存盘时原样写回，无害；`RemoveOrphans` 删 XUnity 两个键的逻辑在新 cfg 上照常生效。现场旧 cfg 里没有含路径的值。
- **`Rewrite` 边界**：`…\MCE` 不会误改 `…\MCEPack`、`…\MCE.bak`、`…\MCE-xxx`；大小写不敏感；`\\` 和 `/` 两种写法都认；JSON 里的 `/` 不会被转义，正斜杠写法能匹配上。
- **staging**：上次残留的 `.copying` 会先删掉；复制或 `Directory.Move` 失败也会清理 staging（问题只在于之后不再重试，见 #2）。旧目录只复制不移动，逐字节保留。
- **跳过的目录**：新目录里的 JSON 没有引用被跳过的 `output/packs`、`exports`（现场 0 处，`check4.txt`）；`MceDirectories.PackOutput` 在新根上两者都不在时返回新路径，不会回落到旧位置。
- **现场路径长度**：复制时不会有文件撞上 staging 超长（`check6.txt`）；运行目录没有长度 258–260 的边界条目；没有超过 64 MB 的 JSON。
- **`queue.json` 的目录字段**：Jobs 的 `WorkDirectory`/`BackupDirectory` 每次由助手 `SetDirectories` 重算，路径写法不一致在这里无害（问题在 `transaction.json` 的 `FileChange.Backup`，见 #5）。
- **简化版 MCE 1.0.3**：`MODs/ModConfigEnhance/src` 全部源码没有任何地方写 `BepInEx\MCE`，只用 `config\ModConfigEnhance` 和 `config\Translation`，不会重新生成旧的运行目录。旧的 `MCE-Recovery.*` 在改名后移成 `.old`，除非用户手动去跑。
- **`ManagerIdentity` 辅助函数**：`IsPackFolder`、`ContainsPackFolder`（两端补 `/` 后比较）、`IsPackFolderPrefixed`、`IsConfigDirectory`、`IsRuntimeDirectory`、`UnderRuntime`（只看第一段）语义正确，调用处用法也对。`IndexOfPackSubfolder` 按「先新后旧」返回而不是按出现位置，但路径里同时出现两种资料夹的情况不现实；`PackPreviewLanguage` 的 `at + marker - 1` 截取结果正确。`PublicationFilePolicy` / `PackContracts` 对新旧名的排除正确。
- **`MceDirectoryMigration` 在新根上**：`RewriteCandidates` 按 `InGameModManager` 字样筛选，`CopyData` 先把根改写成新名，所以能命中；先 `CopyData` 改写、再整理子目录，顺序正确。`MceDirectories.Resolve` 对每个目录单独回退，在新根上同样成立。
- **Awake 顺序**：`RunSplitMigration` 之前没有代码读写运行目录或个人数据目录（`RuntimeLogCapture`、`MceLogApi` 只在内存里；`BindConfig` 只写 cfg）。问题在它**之后**的代码会立刻建目录（#1、#2）。

## 夹具 `split-checks` 漏掉的场景

1. 改名被推迟或失败后，Awake 后续代码（`InstallationWriteLease.Acquire`、`EnsureBuiltInFiles`）会建出新目录，第二次 `Run` 应当仍能完成改名或复制。C 场景只测了「推迟后、什么都没建、下次能改名」，测不到 #1、#2。
2. 复制中途单个文件失败（只读或被占用的文件、staging 超长、目录超长）。
3. 路径别名：场景 A 把 `Steam` 和 `SteamLibrary` 两种写法统一换成了夹具路径，恰好掩盖了 #5。
4. 改写校验只找 `旧根\\` 和 `旧根"` 两种结尾，查不出 `|` 结尾（#4）；也没有检查个人数据 JSON 里残留的 `BepInEx\MCE`。
5. `staleRuntime` 检查排除了所有含 `\.` 的路径，掩盖了 `.transactions`（#7）。
6. JSON 里 `\uXXXX` 转义的非 ASCII 根路径（#8）。
7. 陈旧的旧 `updating.lock`、旧助手实例锁被占用时的 busy 判断（只测了 busy 参数，没测 `Plugin.RunSplitMigration` 的探测逻辑）。
8. 改写进行到一半中断后再跑一次（#9）。
9. 用 `InGameModManager.dll` 宿主的完整环境发布和导入（#3）。
10. 已有 `IGMM\layout-backups\<旧时间>` 时，新根的布局整理备份是否完整（#11）。
