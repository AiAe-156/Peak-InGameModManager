# 近期改动复查报告（2.5.4 / 2.5.5 / MCE 1.0.3）

日期 2026-11-11。只读审查。IGMM 以 git `f526e29`（2.5.5）为准，2.5.4 修复前后对比用 `验证/复查_20261111/2.5.4.diff`；拆分相关文件以 `9e03212` 为准；MCE 以 `1a6f4d4` 为准。现场数据只读查看了 `F:\Games\Steam\steamapps\common\PEAK\BepInEx\config\ModConfigEnhance\` 与 `BepInEx\LogOutput.log`。

## 问题清单（按严重度）

### 1. 中 · MCE 1.0.3 · `ModConfigEnhance/src/ModConfigTreeLayoutPatch.cs:229`（调用链 `src/Plugin.cs:70-73`）
- **缺陷**：小数显示补丁 `ModFloatDisplayPatch.Apply` 挂在树形侧栏的 `Apply` 末尾，不是独立挂载。
- **触发**：① cfg `1. Layout / Tree sidebar = false` 时 `TryApply` 整个不调用；② `Apply` 第 114 行（ModConfig 未装）、第 132 行（找不到 builder 或 `UpdateSectionTabs`）提前 `return`；③ 前面约 100 行里任何一个 `harmony.Patch` 抛异常都会被 `TryApply` 的 catch 吞掉。三种情况下补丁都不挂，PEAK 3.1.0 的模组小数参数仍被显示成整数，手打 `1.25` 会存成错误的值。这是数据正确性问题，跟侧栏布局无关。
- **修法**：在 `Plugin.Awake` 创建 `Harmony` 之后无条件调用 `ModFloatDisplayPatch.Apply(harmony)`（它自带 try/catch，并且查不到目标方法时会自己跳过），从 `ModConfigTreeLayoutPatch.Apply` 里删掉这次调用。IGMM 也是同样的位置（`9e03212:src/ModConfigTreeLayoutPatch.cs:249`，只在 `EnableTreeLayout` 为真时调用），不在本轮范围内，但应该一起改。

### 2. 中 · 2.5.4 · `src/MceDirectoryMigration.cs:170-176` + `src/Updating/MceDirectories.cs:48-53`
- **缺陷**：目录搬了一半时，`MceDirectories` 已经切到新目录，但留在旧目录的那个文件在新目录里没有。程序会在新位置新建默认文件，下次启动合并时这份默认文件反而胜出，真实数据被改名成 `.old-layout`。2.5.4 本来要堵的就是这个问题，现在仍有缺口。
- **触发**：旧 `runtime/` 里有一个文件被占用（杀毒软件、同步盘、编辑器锁定等），`Directory.Move` 抛 IOException，转为逐个文件搬；第 170 行先 `Directory.CreateDirectory(target)`，其他文件搬走，被占用的 `ui.json` 留在旧目录。此时新目录 `data/runtime` 已经存在，`Resolve` 返回新目录，本次运行把默认的 `ui.json` 写进新目录（修改时间是现在）。下次启动时 `MoveFile` 的规则是修改时间较新的留在新位置，于是默认文件留下，真实文件被改名为 `ui.json.old-layout`。夹具 layout-checks 的 B 场景两次运行之间没有模拟插件写文件，所以测不出来。`MoveFile:197-203` 里「源文件较新」的分支也有同类问题：先把目标改名成 `.old-layout`，再移动源文件；如果移动失败，新位置就没有这个文件了。
- **修法**：把留在原处的文件的相对路径记进状态文件，下次合并时这些路径一律让旧文件胜出（新目录里那份当作再生成的默认文件，改名留存）。或者当某个目录有文件没搬走时，`Resolve` 对这个目录继续返回旧目录（例如在旧目录放一个「未搬完」标记）。`MoveFile` 的改名和移动两步要做成可回滚：第二步失败时把目标改回原名。

### 3. 中 · 2.5.5 · `验证/2.5.5改名与跳转/clean_language.py`（产生问题的数据）× MCE `src/Loc.cs:578-581`
- **缺陷**：清理把现场的 `en-us.txt` 和 `zh-tw.txt` 删到只剩三行注释。这个目录拆分后归简化版 MCE 使用；MCE 的 `ParseGroup` 遇到「没有一条有效词条」的文件会直接抛 `NOTICE_LANG_NO_ENTRIES`。
- **触发**：MCE 与 IGMM 共用同一个 cfg 名 `com.aiae.modconfigenhance.cfg`，现场 `[3. State] Language file = en-us`。装上 MCE 1.0.3 后，启动时 `Apply("en-us")` 失败，语言下拉里选 en-us 或 zh-tw 也会报「没有一行有效的『键=译文』」。`WriteIfMissing` 发现文件已存在，不会重新生成。启动时 `Apply` 失败后 `_registered` 已经是 true，`EnsureRegistered` 不会退回 `RegisterBuiltIn`，界面词条可能显示键名或空白（推测，取决于 `LocalizedText.GetText` 对缺失键的返回值）。IGMM 2.5.1–2.5.5 的 `DropRetired` 也能把文件删成只剩注释，所以别的用户也可能遇到。
- **修法**：现场把这两个只剩注释的文件删掉（让 MCE 重新写内置文件），或者从 `备份/2.5.5语言文件清理前_20261111/` 恢复（先征得用户确认）。代码上，MCE 下一版对 en-us/zh-cn/zh-tw 三个内置语言码，在零条目时回落到内置词条，不要整组拒绝。

### 4. 低 · 2.5.5 · `clean_language.py:21-30`（STALE_ORIGINALS / STALE_PREFIXES）
- **缺陷**：从 IGMM 的角度看，被删的「旧名」行确实过时；但它们正是简化版 MCE 1.0.3 现在显示的原文：`FixNaming("ModConfig Enhance")` = `Mod Config Enhance`（自身行名）、manifest 简介 `ModConfig settings page enhancements: …`、`Plugin.DescUiLocalization` 的 `Localize ModConfig's own UI (Search, Default, Clear, filters …) …`。
- **触发**：清理在拆分决定（约 19:55）之前执行（18:29），目录后来留给 MCE。用户回到 MCE 1.0.3 时，侧栏自身行从「[界面]ModConfig增强」变回英文，简介也不再翻译。说明文字那条有 MCE 内置译文兜底，行名和简介没有（MCE 只通过 XUnity 镜像翻译非 `MCE_` 行）。
- **修法**：从备份把 zh-cn 的 `Mod Config Enhance=…`、`ModConfig Enhance=…`、`ModConfig settings page enhancements…=…` 三行补回 `config/ModConfigEnhance/language/zh-cn.txt`（需用户确认）。以后清理规则要先确认目录归哪个产品。

### 5. 低 · 2.5.4 · `src/Plugin.cs:121-135, 182`（`RemoveOrphans`）
- **缺陷**：删的两个 cfg 键「Switch XUnity language with the language file」「Disable XUnity machine translation」是简化版 MCE 1.0.3 仍在使用的设置，而且两者 GUID 相同、共用 `com.aiae.modconfigenhance.cfg`。
- **触发**：用户曾在旧 MCE 里把其中一个改成 false，运行过 IGMM 2.5.4/2.5.5 之后再装 MCE 1.0.3，这两项会回到默认 true，MCE 启动时又去清 XUnity 的机翻端点（`TameEndpoint`），违背用户原来的选择。本机两项原值都是 true，没有实际影响。另外，现场 cfg 里还剩 `Language row only`、`Translation tools`、`Mirror language file to XUnity` 三个更旧的孤儿键没有清掉，只是杂乱，无功能影响。
- **修法**：1.0.0 起 IGMM 用自己的 cfg，旧 cfg 不应该再去动。确认 `9e03212` 之后的 `RemoveOrphans` 只作用于 IGMM 自己的 cfg 即可；如果要提示用户，可以在 MCE 的 CHANGELOG 里写一句。

### 6. 低 · 2.5.4 · `src/Loc.Import.cs:156-160`（`LanguageMigration.Run` 合并）
- **缺陷**：修复说明称「写失败时原文件都还在原处」，但删除循环中途失败时并非如此。
- **触发**：同组多个分包，复制进备份后，`foreach File.Delete` 删到第二个文件时遇到占用、抛异常，第一个文件已经删了，`.mce-merge.tmp` 留在目录里，标记没写。下次启动重新合并时，这一组只剩没删掉的文件，已删文件的译文不会再合并进来（只在上一次的 `_迁移前备份_时间` 里有）。
- **修法**：先 `File.Move(staged, target)`（如果目标是组里的某个文件，先把它改名为 `.mce-merge.old`），再删除其余文件；或者删除失败时把已删的文件从备份复制回来，再抛异常。

### 7. 低 · 2.5.4 · `src/Loc.Escaping.cs:49-62`（`Unescape`）
- **缺陷**：新规则把 `\\` 解成一个反斜杠，旧版写出的文件里，原文本身含两个连续反斜杠的行，键会对不上。
- **触发**：旧版 `Escape` 不转义反斜杠，原文 `\\server\share` 或 `a\\b` 会原样写成 `\\server…`；2.5.4 读回来变成 `\server…`，这条译文失效。现场 zh-cn.txt 扫过，没有这种行（`recent-review/scripts/bs.py`，0 处），所以这里是理论兼容问题。
- **修法**：可以接受，在 CHANGELOG 里说明即可；如果要兼容，读取时对查不到的键再用旧 `Unescape` 试一次。

### 8. 低 · 2.5.4 / 2.5.5 · `src/Loc.Import.cs:200`（`DropRetired` 的 `.mce-language-v3` 一次性标记）
- **缺陷**：2.5.4 新增的退役键 `NOTICE_IMPORTED`、2.5.5 新增的 `TIP_OPEN_DIR_V2`，对已经有 v3 标记的用户永远不会从文件里清掉。修复说明写的是「从个人文件里清掉」。
- **触发**：用户运行过 2.5.1–2.5.3（已写入标记），升级到 2.5.4/2.5.5 后，`DropRetired` 第一行就返回。读取时 `Loc.cs:660` 会跳过这些键，所以没有显示错误，只是文件里留着过时的行。
- **修法**：标记里记一个退役清单的版本号（或清单哈希），版本变了就再跑一次。

### 9. 低 · MCE 1.0.3 · `ModConfigEnhance.csproj:22, 63`
- **缺陷**：`DeployDir` 仍指向 `plugins\[界面]ModConfig增强-ModConfigEnhance\`，这个目录现在不存在；`Deploy` 目标只要不传 `EnableDeployment=false` 就会执行。
- **触发**：在 MCE 工程里直接 `dotnet build`，会新建这个目录，把 MCE 1.0.3 装进游戏，与 IGMM 同时加载。AGENTS 写明「MCE 1.0.3 不部署进游戏」，而 `check_deploy_dir.py` 只会把这种情况报成 NEW。
- **修法**：把 MCE 的 `Deploy` 条件改成 `'$(EnableDeployment)' == 'true'`（默认不部署），或者清空 `DeployDir`。

## 已检查但没问题的方面
- **2.5.4 正则**：与 XUnity 5.6.1 反编译一致：`TextTranslationCache` 倒序取第一个 `Match`、用 `Match.Result`、命中即停；`UnescapeXUnity` 与 `TextHelper.ReadTranslationLineAndDecode` 一致，仅两处差异（小写 `%3d`、非法 `\u` 不报错），无实际影响。
- **2.5.4 转义与导入**：`Escape`/`Unescape` 往返正确（含末尾反斜杠、`\=`、`\` 后跟 n），`FindUnescapedEquals` 的状态扫描正确；`r:` 行经导入、合并时 `Unescape` → `Escape` → `UnescapeXUnity`，结果不变；`IsPlaceholder` 正确跳过完整导出里预填的英文。
- **2.5.4 作者包与 cfg 清理**：`PublishedPack` 托管与未托管两种情况下的 `profiles/index.json` 路径都对（现场存在），`LanguageDirectories` 不会重复扫描；`RemoveOrphans` 反射的 `OrphanedEntries` 与 BepInEx 5.4.23 的私有属性同名同类型。
- **2.5.4 跳转取消**：`CancelOpen`/`OnDisable` 的取消路径完整。
- **2.5.5 跳转快捷键页**：`FinishOpen` 先收尾再切页的顺序正确（`OnDisable` 时 `Opening` 已是 false，不会再取消），失败时 `FailOpen` 复位。
- **2.5.5 改名**：整句改名的调用处与词条目录同步改了，没有残留产生旧文字的代码；被代码当作匹配键的串（`ConfigurationIssueReport` 的 `MCE required`、`MCE enablement 1`、`MCE.WorkerProtocol`、`MCE_` 前缀、`MCEPack`）都没有动。`DiagnosticUiLanguage` 改过的短语没有残留的旧生产者；日志 `CategoryLabel` 的写入方和比较方是同一个常量；`PackReportText` 标题只用在内存里的隐藏集合，不持久化。新加的 4 条 `ConfigTerms` 与实际 cfg 原文逐字一致；`TIP_OPEN_DIR_V3` 与退役键 `TIP_OPEN_DIR_V2` 配套正确。
- **2.5.5 清理规则**：没有误删其他模组的译文或快捷键描述；被删的 10 个 `MCE_` 覆盖在 IGMM 里都有内置词条。
- **MCE 1.0.3 补丁本身**：依赖的成员都存在（3.1.0 里 `FloatSettingUI.GetFormattedString(float)` 是私有方法；`inputField` 公有；`_listeningSetting` 是 protected，经 publicize 可访问；`IBepInExProperty` 在 MCE 1.0.2 已经用过）；聚焦时回传原文的逻辑和原版 `OnChanged` 用的是同一种文化格式。

- **MCE 1.0.3 共存提醒**：三语齐全；`PluginInfos` 按 GUID 字母序加载，IGMM 先于 MCE，`Awake` 里的检测能生效。
