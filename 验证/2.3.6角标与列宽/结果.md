# 2.3.6 名称列角标、列宽、分组色条与折叠（2026-11-09）

接原会话「模组代码逻辑审查」的三件事（该会话停在中途，本会话接手）。

## 用户提的问题与查到的原因

1. **停用模组右上角的小角标是什么、为什么悬停没提示。**
   - 停用模组上最常见的是两种：**蓝色＝未读变动**（如 UBImGui、地形定制器在当前整合包环境里被记为「不再记录 / 首次记录」），**蓝色＝待重启**（迷你景观台、PLL 库 11-03 在整合包工作区里应用过启停，`pending-restart` 记录在 `MCE/packs/9631…/workspace/runtime/pending-profile.json`）。两者同色，没法区分。
   - 悬停无提示的原因：未读变动角标只有 8×8 的小方块能接收射线（宿主框上的透明 Image 加在了 `StatusChip` 返回的 16×16 盒子上，但盒子在 `Create` 里没被设成可点）；名称文字只按自身宽度布局，角标周围大片区域落在「整行」上，悬停只会触发行本身。
   - 槽位是固定位置：未读 0、更新 1、待保存 2、待重启 3……一个模组只有「待重启」时，角标落在离右边四格远的位置，看起来像飘在名称中间、和其他行不对齐。
2. **其他角标有没有问题。**
   - 资源包（青 → 原为浅绿）与「有新版本」绿色几乎一样；散放 DLL（粉 → 原为浅紫）。
   - 资源包没有 DLL，加载器永远不报「已加载」：启用的资源包方框是灰色，悬停写「文件已启用但本次未加载，原因见游戏日志」——误报。
   - 嵌套角标的槽位依赖「待处理角标数」，有待处理时会和它们错位重叠。
3. **角标间距太大、名称列太窄、简介太长。**

## 改动

- `StatusChip`：间距 11→10，留白 `Step`→4；槽位改为**优先级**（未读 0、更新 1、待保存 2、待重启 3、嵌套 4、资源包/散放 5），由 `StatusLane`/`StatusChipSlot` 在显示/隐藏时**从右边紧排、无空位**；`raycast` 时整个 16×16 盒子加透明 Image 作为热区。新增 `Restart` 紫色，资源包青色、散放粉色。
- `ProfilePendingMarkers`：待重启改紫色并用 `RestartSlot`；行内启停角标的悬停先写一行「橙色：这项启停改动还没保存…」或「紫色：已应用，重启 PEAK 后生效」，再接原有的启停详情。
- `ChangeLedger.UpdateDot`：未读角标走 `raycast: true`。`AvailableUpdateDot.Name` 固定用 `UpdateSlot`（紧排后不再需要按有无未读换位）。
- `OverviewListView`：标题预留只按实际显示的角标数；嵌套/资源包角标改用优先级；三种角标提示补颜色名。
- `ModEnablementPresentation.Active/Tint`：资源包按文件是否启用判定当前状态；三处启停颜色统一走 `Tint`。
- `ModNameLayout.ColumnWidth`：23%/310 → 27%/370（×1.2），简介列相应变短。
- 分组色条（原会话已改，本次构建）：`OverviewUi.Rail` 纯色矩形，替换概览、快捷键页、智能分组、方案列表四处的圆角 Panel（2–3 像素宽时圆角 9-slice 会变成透镜形）。
- **分组折叠不再整页重建**：`RenderFold()` 只在折叠/展开分组和基础组件区时使用。已建好、数据未变（`RowUpdateStamp` 一致）的模组行停放到不激活的 `ParkedRows` 下，重新布局时同一个 `VirtualRow` 对象原样搬回新位置，只更新序号、拖放区与启停状态；被折叠掉的行留着等下次展开。宽度、语言、作者模式、来源标签开关任一变化，或任何其他 Render，都丢弃停放行、照旧全量重建。行内点击改用 `VisibleIndex(mod)` 取当前序号（原先捕获构建时下标，搬位后会错）。
