# 2.4.3 修复导出日志时游戏崩溃（2026-11-10）

## 现象
日志窗「选择位置并导出」→ 游戏立刻崩溃（Unity 崩溃框）。转储 `%LOCALAPPDATA%\Temp\LandCrab\PEAK\Crashes\Crash_2026-11-10_115737087\`。

## 取证
`output_log.txt` 第 924–939 行原生栈：
```
KERNELBASE RaiseException ← mono marshal … ← Marshal:SizeOf (System.Type)
← ModConfigEnhance.Overview.LogSavePicker:Select (string)
← ModConfigEnhance.Overview.LogWindow:BeginExport ()
```

## 根因
`LogSavePicker.Dialog` 把 `[MarshalAs(LPWStr)] StringBuilder File` 写成 OPENFILENAMEW 的字段。StringBuilder 只能作 P/Invoke 参数；.NET 抛 MarshalDirectiveException，Unity Mono 在 `Marshal.SizeOf` 里中止进程（托管 catch 接不到）。备份中最早 10-30 的版本已是这样写。

## 修复
- `LogSavePicker` 照 `IntroductionFilePicker`：`AllocHGlobal` 缓冲 + `finally FreeHGlobal`，字段按 OPENFILENAMEW；API 改 `TrySelect(name, out path, out failure)`，取消返回 true+null。
- `LogWindow.BeginExport`：对话框不可用 → 存 `BepInEx\config\ModConfigEnhance\export\<名>.zip`，状态行「无法打开保存对话框，已改存到固定位置：…」（三语经 `DiagnosticUiLanguage`），日志 Warning 记原因。
- 回归新增 `interop-structs`：`interop_checks.py` 扫 src/Updater/Desktop 全部 `[StructLayout]` 类型（现 4 个）禁止 StringBuilder 字段，断言保存框自管缓冲与兜底。反向对照：换回旧 LogSavePicker 报 5 项失败。

## 验证
三项构建 0/0；回归 28/28；部署 `deployment_20261110_200718` 50 文件，备份 `备份/部署前_2.4.3日志导出崩溃_20261110_200718/`。

## 过程备注
第一次构建失败：Python heredoc 把 `"\n"` 写成了真换行进 C# 字面量（20 个 CS1010），改用字节值替换后通过。

## 未验证
实机：另存为窗口能否正常弹出与保存；固定目录兜底路径只在对话框失败时走，未实际触发。
