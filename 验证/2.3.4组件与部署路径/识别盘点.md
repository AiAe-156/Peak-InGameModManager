# 2.3.4 识别盘点（只读，2026-11-09）

现装 `BepInEx/plugins` 按形态分类（探针 `probe_plugin_shapes.py`，输出 `plugin-shapes.txt`）：

| 形态 | 数量 | 概览现状 |
|---|---|---|
| 文件夹 + manifest + 插件 DLL | 55 | 有行 |
| 文件夹无 manifest + 插件 DLL（本地包） | 2 | 有行 |
| 插件 DLL 全部 `.dll.<后缀>` 停用 | 3（PLL_Library `.d`、TerrainCustomiser、UBImGui 各 `.disabled-framedoc-test`） | 有行（按停用副本读出插件） |
| plugins 根目录散放 DLL | 0 | 有行（规则已支持） |
| 只有 manifest、没有任何 DLL | 4 | **无行** |
| manifest + 只有库 DLL（无 BepInPlugin） | 1 | **无行** |
| core/patchers 平铺布局（MonoDetour 两个） | 2 | 2.3.3 起在基础组件里有行 |

## 只有 manifest 的 4 个
- `3玩法模组/AeralisFoundation-PLL_Fog_Resources`：manifest + `NativeFog.bundle`（资源包，被 PLL 地图库用）。
- `3玩法模组/AeralisFoundation-Unified_Ray_Tracing`：manifest + `unifiedraytracing`（资源包）。
- `MonoDetour-MonoDetour`：manifest + 说明文件，DLL 在 `core/` 根（同一个包的 plugins 那一半）。
- `0基础模组/[功能]ESC队友资料卡Profile_Cards-0.1.5`：**探针误判**，DLL 在 `plugins/` 子目录里（打包结构），实际有行。

## manifest + 只有库 DLL 的 1 个
- `0基础模组/[界面]ModConfig增强-ModConfigEnhance`：MCE 旧版 2.0.0 停用副本，`ModConfigEnhance.dll` 被改名成 `ModConfigEnhance.dll1`（不是 `.dll.<后缀>`，所以连停用副本也认不出），只剩 `Markdig.dll` 库。

## 用非标准方式停用的
- `ModConfigEnhance.dll1`：后缀不是 `.dll.xxx`，现有规则不认。
