## 实施

- Capture 保留运行值并额外捕获磁盘字段存在性和值；恢复草稿随快照兼容持久化。Reconcile 按保存范围比较运行/磁盘双基线，未编辑字段采用外部值，同值通过，编辑冲突走原 MCE_EXTERNAL_CONFLICT UI。overwrite 仍先合并未编辑项，不回退无关外部值。旧恢复缺磁盘基线时保守检查。已删除且未编辑字段不重新创建。
- 将刚核验的磁盘/运行代次传入 PrepareApply；OfflineConfigurationTransaction 接受可选字段基线，保留原原子替换前再检查及失败回滚。
- Applied 在 Save 前构造成功快照，跳过参数与启停保留正式旧值，工作目标只留恢复草稿；applied 快照只接受成功项。旧恢复放弃仅在正式内容仍等于旧恢复目标时修复，避免覆盖后来的外部预设内容。
- 新局交付真实 BepInEx 文件/字段事件订阅，避免 OnSettingChanged 吞异常导致伪成功。已成功订阅者和桥接调用在重试中不重复；写 pending 成功后才更新内存及清交付记录。ModConfig handler 尚未就绪视为失败；GameRestart 不在新局通知。保存改回原值取消 pending。

## 边界与剩余验收

- 保持当前语义：保存延迟项仍更新 ConfigEntry.Value 并落盘，仅事件及 ModConfig 回调延迟。直接轮询 Value 的第三方可以提前读到新值；若要求连轮询都延迟，需要另行扩大运行/持久值分离设计，不在本次伪称解决。
- 第三方回调若自身先产生副作用再抛错，重试无法通用保证副作用恰好一次；成功返回的独立订阅者不会重发。进程崩溃与外部副作用之间也无通用原子事务。
- 新局 ModConfig 桥接用生产方法＋SettingsHandler 适配桩，实际游戏控件/第三方回调仍需实机复核。
- 尚未执行父代理最终完整 21 步回归；未覆盖完整 OverviewProfileStore 与真实 UI 导出入口（已覆盖实际 ProfilePairPersistence 与 Applied 生成内容）。
