# MCE 概览：悬停丝滑与首次打开提速方案（2026-10-30，待确认，未实施）

> 目标：任何悬停框**无人为延迟**地即时出现，鼠标在概览里快速乱晃不掉帧；首次打开概览明显变快。
> 约束（用户指定）：行内图标按钮（设置/主页/文件夹等）**外观与动效保持原样**；不靠加大悬停延迟。
> 边界：只改 `ModConfigEnhance/src`，不部署、不动真实配置/库存/队列；改前快照到 `备份/20261030_悬停性能前/`。
> 基线：Unity 6000.3.15，TMP / uGUI 为游戏自带；PEAKLib.UI 1.7.1 按钮模板 = 主菜单 `UI_MainMenuButton_LeaveGame (2)` 的副本。

## 阶段 0：先装计量（必须，约半天）

目的：每项改动都有前后对比，不凭感觉验收。

**实施**
1. 新增 `src/Overview/Diagnostics/UiPerfProbe.cs`（仅当配置 `Diagnostics.UiPerfProbe=true` 时启用，默认关闭）：
   - `Canvas.preWillRenderCanvases` 记起点、`Canvas.willRenderCanvases` 记终点，统计每帧 UI 布局/图形重建耗时（Unity 6 两个事件都公开可用）。
   - 计数器：提示内容生成次数、TMP 测量次数（包一层 `MeasureContent/GetPreferredValues` 调用点）、关系索引构建次数（已有 `ComponentRelationshipTree.IndexBuilds`）、`VisibleBounds` 调用次数、`GC.CollectionCount(0)` 增量。
   - 每 5 秒输出一行汇总到日志：`[UI计量] 帧数 / UI重建 avg/max ms / 提示生成 n / 测量 n / GC0 n`。
2. 打开概览时一次性统计并写日志：概览根下 `Animator` 总数、其中 `isActiveAndEnabled` 的数量、`PeakMenuButton` 数量、`TMP_Text` 数量。
3. 用现有 FrameDoctor 做 60 秒「快速乱晃」×3 轮作为基线，结果存 `验证/悬停与首开性能20261030/基线/`。

**避雷**
- 事件回调里不要分配：用 `Stopwatch.GetTimestamp()`，汇总用预分配数组。
- 订阅静态事件一定要在插件销毁/开关关闭时退订，否则场景切换后泄漏。
- 计量开关默认关，不能把计量本身变成新的帧开销。

## P1：提示层画布隔离（解决 R1，最高优先，风险低）

**实施**
1. 新建 `src/Overview/HintLayer.cs`：在概览页根（`OverviewPage` 的 `transform`，即 `ModalParent` 同级层）下建 `MCE_HintLayer`：
   - `Canvas`：`overrideSorting=true`，`sortingLayerID/sortingOrder` = 根画布值 + 50（低于模态层，见避雷）；
   - `additionalShaderChannels` **复制根画布**（TMP 需要 TexCoord1/Normal/Tangent，否则字重/描边异常）；`pixelPerfect` 跟随根画布；
   - 挂 `GraphicRaycaster`（固定模式依赖卡要能滚动/悬停卡片本身），普通提示内部 Graphic 保持 `raycastTarget=false`。
   - 全屏拉伸，`CanvasGroup.blocksRaycasts=false` 于层根，卡片自身 CanvasGroup 再按 `_fixed` 打开。
2. `OverviewListView._hint` 与 `OverviewDependencyHints._card` 的父级改为 HintLayer（目前是 `parent`=_body）。坐标换算目前都以 `_parent`/`_root` 为参照，需要统一改为以 HintLayer 的 RectTransform 为参照，把 `_root`/`VisibleBounds` 的矩形换算到 HintLayer 本地坐标。
3. **鼠标不动不改位置**：`PositionHint`/`Position(Pointer)` 前比较上一帧指针屏幕坐标（差值 < 0.5px 跳过）；写 `anchoredPosition` 前比较新旧值，只在变化时写（RectTransform 赋同值也会标脏）。
4. 提示框不再反复 `SetActive`：改为常驻激活，隐藏用 `CanvasGroup.alpha=0`（或 `Canvas.enabled=false` 整层）；内容替换只改 `text`。层内只有 1~2 个元素，alpha 变化代价极小，且不会触发列表画布。

**避雷**
- **遮罩**：`MaskUtilities` 遇到 `overrideSorting` 的子画布会停止向上查找 RectMask2D，提示会**跳出视口裁剪**——这正是想要的效果。但卡片内部自己的 `RectMask2D`（viewport）必须保留在卡片之下。
- **CanvasGroup 继承**：嵌套 Canvas 依然受祖先 CanvasGroup 的 alpha 影响。HintLayer 的父级不要放在 `OverviewCascade` 做淡入的行或表头下面；放页面根。模态打开时，`OverviewUi` 会改上一级选择对象的 CanvasGroup，需要确认不会把提示层一起压暗（可设 `ignoreParentGroups=true`）。
- **排序**：sortingOrder 必须低于 `MCE_Modal`/确认框，否则提示盖在弹窗上。现有逻辑是「有模态就 HideAllHints」，保留这层兜底。
- **相机**：根画布若不是 Overlay，HintLayer 继承根画布的 worldCamera；`ScreenPointToLocalPointInRectangle` 的相机参数用根画布的，**缓存起来**，不要每帧 `GetComponentInParent<Canvas>()`。
- 快捷键页也在复用 `_list.BindDependencyHint`，HintLayer 必须挂在两个页都共有的父级下面。
- 页面关闭（`OnClosed`/`Dispose`）时要销毁或隐藏 HintLayer；页面实例常驻，所以只建一次。

**验收**：提示显示并跟随鼠标时，计量里的「UI重建」耗时与提示关闭时基本一致；中、英、繁三种语言下截图位置、裁剪与原来一致；固定模式卡片可滚动。

## P2：依赖卡片内容生成降到 O(n)（解决 R3/R4，风险中）

**实施**
1. **显示代次索引**（在 `SharedRelationshipSnapshot.Build` 结束时一并生成，挂在 Snapshot 上）：
   - `Dictionary<string id, OverviewMod>`：覆盖 Guid、`guid:`前缀、PluginGuids、SourceKey、node.PackageKey 所有别名；
   - `Dictionary<string, InfrastructureOverviewModel>` 按 Key；
   - `ComponentRelationshipLabels.Mod/Component/Name/Version` 先查字典，查不到再走原线性兜底（保证行为不变）。
2. **显示序号**：`Render()` 生成 `_visible` 后同时建 `Dictionary<OverviewMod,int>`，`GetDisplayNumber` 改为查字典。
3. **测量改为一次排版取行高**（核心）：
   - 把全部行拼好后**只调用一次** `_text.SetText` + `ForceMeshUpdate`，再从 `textInfo.lineInfo` 读出每个源行结束位置对应的累计高度（源行用 `\n` 分隔，可以找到每个 `\n` 字符所在 lineInfo 的 `descender`）；
   - 非固定长卡片的截断：用累计高度二分找到最后一个放得下的源行，最后 `SetText` 一次截断后的文本；
   - 结果：每张卡片最多 2 次排版，替代现在的 N 次。
4. **多条 LRU 缓存**：键 = (目标身份 key, 图代次引用, 库存代次, 语言代次, `_chains`, `_fixed`, 可视宽度取整到 8px, 字体资产实例 ID)，容量 64；值 = 已经拼好的富文本 + 测量结果（宽、全高、截断文本）。命中时只做 `SetText` + 摆放。
5. **VisibleBounds 去分配**：用 `List<RectMask2D>` 字段配合 `GetComponentsInParent(true, list)` 的非分配重载；结果按 (目标, 屏幕尺寸, 滚动位置) 缓存，每帧最多算一次；`Camera` 属性改为打开页面时缓存。
6. **Update 中的数据变化检测**（`VisibleBounds()!=_layoutBounds` 等）改为只在代次计数变化或屏幕尺寸变化时检查，而不是每帧都算一次矩形比较。

**避雷**
- **富文本与 `\n` 的对应关系**：`WrapTokens` 会插入 `\u200B`，`<indent>` 标签不产生字符；只能用 `textInfo.characterInfo[i].character=='\n'` 来定位源行边界，不能用字符串下标。
- 截断后的文本必须和测量用的完全一致（原代码注释特意强调过「rejected probe must not remain」），只能多测，不能少测。
- LRU 键漏掉某个维度就会显示旧内容。必须包含：语言、链条开关、固定/跟随模式、字体（字体回退切换时 `MceRegularFont` 的 fallback 会变）、库存代次、`SourceUi.DependencyGraph` 引用、窗口宽度。宁可多失效。
- 别名字典必须完整复刻 `Mod()` 原有的三条匹配规则（SourceKey 需满足 SourceConfirmed + 无冲突 + ShopInstalled.Key）。查不到时一定要走旧逻辑兜底，并写回归测试对比新旧结果一致。
- 原来的 `Show()` 在 `same` 目标时有 `_selected` 保留语义，改缓存时不能破坏。

**验收**：在 `PerformanceChecks` 里加离线测试：随机 200 模组、深度 2、每向 8 项，新旧 `Lines()` 输出逐字一致；每张卡片测量次数 ≤2；同一目标第二次显示时测量为 0。

## P3：悬停延迟归零与内容预热（配合 P2，解决「即时」）

**实施**
1. `HoverDwell` 改为「同帧合并」，不再按时间延迟：`Enter` 只记录最后一个目标，在本帧 `Tick` 时取出并立即显示。一帧内扫过多个目标只处理最后一个（这不是延迟，同一帧本来就只会显示一个）。依赖卡的 `_showAt=+.15f` 同样改为下一次 Tick 立即显示。
2. **空闲预热**：列表静止时（滚动速度≈0、没有拖动、没有输入、没有模态），每帧最多用 1.5ms 预算（Stopwatch），按「当前视口行 → 视口上下各一屏」的顺序，为依赖卡生成 P2 的缓存条目（只生成字符串和测量结果，不显示）。滚动、语言或代次变化时清空队列重新排。
3. **兜底**：极端情况下（缓存未命中且依赖链很长），先立即显示标题和 ID 两行的简版卡片，内容在下一帧补全。主线程单帧不超过约 2ms。

**避雷**
- 预热会调用 `GetPreferredValues`，也会把字形写入图集（会触发 P5 的上传）。所以 P5 必须先于或同时上线，不然预热本身就会制造卡顿。
- 预热只能在主线程做（TMP 测量不是线程安全的），所以一定要有时间预算。
- 修改 `PerformanceChecks/Program.cs` 中现有的「150ms gate」断言，改为「同帧多次 Enter 只出一次、零延迟出现」，否则回归会失败。
- 普通提示（`ShowHint`）本身很便宜（单段文本 + 已有测量缓存），归零后只靠 P1 就能做到丝滑，不需要预热。

## P4：按钮 Animator 静息休眠（解决 R2，外观保持原样，需要阶段 0 确认后再做）

**用户要求外观与动效不变**，所以不替换按钮，只让**不在动的 Animator 停下来**。

**实施**
1. 新增组件 `AnimatorRestGate`，在 `OverviewUi.Button` 创建按钮时挂上（只限概览/MCE 自建按钮）：
   - 创建后等第一次进入 Normal 状态并播完，再设 `animator.keepAnimatorStateOnDisable=true`、`writeDefaultValuesOnDisable=false`，然后 `animator.enabled=false`；
   - 实现 `IPointerEnter/Exit/Down/Up/Select/Deselect`：**先** `animator.enabled=true`，**再**按 `button.animationTriggers` 中对应名称手动 `ResetTrigger` 全部后再 `SetTrigger(对应状态)`，复刻 `Selectable.TriggerAnimation` 的逻辑；
   - 回到 Normal 且 `GetCurrentAnimatorStateInfo(0).normalizedTime>=1`、没有过渡、没有悬停/选中时，再次 `enabled=false`。这项检查只在 Animator 启用期间每帧做（数量很少）。
2. 阶段 0 若显示 Animator 数量很少，或停用后帧时间没有改善，就**取消 P4**。

**避雷**
- `Selectable.TriggerAnimation` 要求 `animator.isActiveAndEnabled`。Button 组件排在我们的组件之前，先收到 PointerEnter，那时 Animator 还是停用状态，触发会被丢掉。所以必须由我们**自己补发 Trigger**，不能指望 Button 自己发。
- 停用前必须设好 `keepAnimatorStateOnDisable=true`，否则停用、启用会重置到默认姿态（缩放跳变）。
- 悬停音效是由动画启用 SFX 子物体触发的，只要 Trigger 正常补发，音效就保持原样。实机要确认音效没有丢、也没有重复播放。
- 禁用状态（`interactable=false`）的按钮也要走 Disabled 触发。代码里有 70 处地方会改 `interactable`，需要监听状态变化：可在 `UiActionStyle.Refresh` 中检测 enabled 变化时唤醒一次。
- 虚拟行回收（`ReleaseRow`）会销毁行，不影响 P4；但驻留缓存（`StableRowCache`）里的行重新激活时，要在 `OnEnable` 中重置为休眠前的姿态。
- 手柄导航的 Select 也要唤醒，否则焦点高亮动画会失效。

## P5：字形预热（解决 R5，风险低）

**实施**
1. `Reload()` 完成后，收集全部会出现在提示/卡片里的文本：显示名、原名、说明（翻译后）、作者、分组名、依赖卡固定词条（各语言 `Loc` 的当前语言值）。对每个字体资产（主字体与回退链中的 NotoSansSC/TC）计算缺失字符集合。
2. 分帧调用 `fontAsset.TryAddCharacters(chunk)`：每帧最多 64 个字符，或 2ms 预算。只对 `atlasPopulationMode==Dynamic` 的资产调用，并且只对**回退链中真正会提供该字符**的那个资产调用（中文 → NotoSansSC）。
3. `TreeArrow()` 在页面 `Initialize` 时调用，后续只读取静态结果。

**避雷**
- 这些是**游戏共享的字体资产**，加字形会改动游戏的图集（项目里 `MceRegularFont` 注释写过「Shared game assets are read-only」）。往动态图集里加字形属于正常的运行时行为，游戏自己也是这么做的，但不能 Clear/重建图集，也不能改图集尺寸。若用户介意，可改为只预热 MCE 私有字体（但中文实际由游戏字体提供，那样效果有限），需要你决定。
- `TryAddCharacters` 每次调用都可能 `Apply` 整张 4096² 贴图（约 16MB 上传），所以**一定要合批**：一次调用传入一整块字符，不要一个字一个字地加。首批放在页面打开前（主菜单空闲时）最好。
- 4096² 图集被填满后，`isMultiAtlasTexturesEnabled` 若没有开启，会添加失败。只做尝试，失败就忽略，不要强行开启多图集（会改变游戏资产行为）。

## P6：首次打开提速（解决 R7，风险中）

**实施**
1. **只扫描一次**：`OverviewRepository.Reload` 已经执行了 `Scan` 得到 `installed`，保存为 `LastScan`（带库存代次）。`OverviewListView.Reload` 在代次一致时直接复用，不再调用第二次 `Scan`。注意列表会修改 `OverviewMod` 的状态（Rule、分类等），复用时要确认两边用的是同一份对象，不要和 `Profiles.Initialize` 里的数据交叉污染；拿不准时复用前做浅拷贝。
2. **字体诊断**：`OverviewFontReport.Run` 改为只在 `Diagnostics` 开关打开时运行（省 36ms）。
3. **主菜单空闲预建**：在 `Title` 场景稳定 3 秒后，主菜单空闲时（没有输入焦点、帧时间正常），分帧执行 `new OverviewRepository()` 中的 IO 部分和页面骨架 `Initialize`，页面保持 `SetActive(false)`。点击时只做切换和 `OnOpened`。
4. **IO 放后台**：`Scan` 中的 Cecil 元数据读取（`AssemblyRecords`）、清单解析、`state.json`/profiles 反序列化都是纯 IO，放到 `Task.Run`。`Chainloader.PluginInfos` 读取放在主线程，先拍快照再交给后台。
5. **首帧只建视口行**：虚拟行已经是按需建立的。确认首帧只绑定视口和上下缓冲区（当前缓冲为 2 行，合理）；分组标题仍然常驻，可以一并纳入虚拟化。

**避雷**
- 预建期间用户可能进入别的页面或开始游戏：场景切换时取消（`CancellationToken`），丢弃半成品，下次再建。
- 后台线程**不能**碰任何 Unity 对象（包括 `Paths` 以外的 Unity API、`Application.*`），也不能读 `BepInEx.Configuration` 的 `ConfigEntry.Value`（非线程安全）。
- `OverviewRepository.Reload` 里有首次迁移和备份写盘（`before-profiles-*`）。预建时要保证这个过程只执行一次，并且和点击打开不会并发（用同一个 `Task` 去重）。
- `OverviewPageCache` 的 FileSystemWatcher 代次在预建后可能发生变化：打开时照常走 `PrepareCachedPage` 的变化检测，不要因为已经预建就跳过检测。
- 不能在 Pretitle/加载画面期间预建（PEAKLib 的按钮模板在 `MainMenu.Start` 之后才存在）。

## P7：维护循环降频（解决 R6，可选，风险中）

**实施**：把 `OverviewMaintenance` 的 0.2s 全量巡检拆开：
- `UiActionStyle`：主题变化（`TimeThemeBridge` 加一个 `Revision` 计数）或 `interactable` 变化时才标脏；
