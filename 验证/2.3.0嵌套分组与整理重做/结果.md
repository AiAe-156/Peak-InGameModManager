# 2.3.0 嵌套分组 + 目录整理重做 + 首次智能分组

所有决定见同目录 [决定.md](决定.md)，计划见 [实施计划.md](实施计划.md)。

## 做了什么
- **数据**：`OverviewGroup.parentId`；纯逻辑 `src/Overview/GroupTree.cs`（树序/深度/路径/子树/折叠/防环防超三层/删除上移/同级排序/导出版本）、`GroupPalette.cs`（顶层不同色系、子级同色系子色）。
- **兼容**：含嵌套分组的 `profile.json`、`pack-information.json` 写 `schemaVersion 2`，无嵌套写 1；读取接受 1/2；配置快照与索引仍只认 1（旧版拒绝导入嵌套方案）。编辑器回滚补 `parentId`；变更核对显示上级分组变化。
- **概览列表**（`OverviewListView.Groups.cs` + 主循环）：树序、缩进标题、每级色条、子树计数、父级折叠连带、右键菜单（新建子分组/编辑/移到顶层/删除）、分组标题拖到另一标题即挂为子分组。
- **编辑器**：上级分组下拉、左栏树缩进、同级上下移、删除上移一层、新组默认色走色系。
- **其它视图**：ModConfig 侧栏（缩进+每级色条+子树计数+祖先折叠）、快捷键页、管理中心模组选择器、日志窗口、依赖悬浮、更新进度、方案变更核对、商店安装选分组。
- **嵌套模组**：`NestedMods.cs` 判定（打包结构 plugins/BepInEx/patchers、同名 manifest 不算）；`OverviewMod.Outer/Inner`；琥珀色角标；启停 `SetWithNested`（外层停连带、记下并恢复内层，外层关时内层不可开）。
- **目录整理**：`src/Updating/GroupFolderPlanner.cs`（纯逻辑）+ `Updater/GroupLayoutPlanner.cs`（采集与转换）；插件发「行」(`LayoutQueueRow`)，worker 有行即走新规划器。模组文件夹不改名；分组路径 = 分组名链；分类文件夹改名为分组名；拆嵌套（先内后外）；未分组 → 「未分组」；旧副本跟同名；无 DLL 跟依赖它的；重名加版本号；MMHOOK/MCEPack 不碰；管理器最后。执行端：校验最终位置、空壳目标可复用、回退逐级清理空分组目录。去掉「预览分组并使用译名」。
- **预览界面**：`LayoutReviewModel.cs`/`LayoutReviewView.cs` 重做为按文件夹嵌套的卡片树，「N 个文件夹 · 共 M 个模组」，改名卡片标注来源，空文件夹带「删除」→ 回收站（`RecycleBin.cs`，`SHFileOperationW` 允许撤销，只收 plugins 内无 DLL/manifest/链接的文件夹）。
- **首次智能分组**：`SmartGrouping.cs`（纯逻辑）+ `OverviewPage.SmartGrouping.cs`；没有任何分组、plugins 有分类文件夹时进入概览弹一次，确认即保存，「不用了」写标记 `smart-grouping-offered` 不再弹。
