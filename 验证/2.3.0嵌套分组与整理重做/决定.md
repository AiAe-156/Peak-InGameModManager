# 2.3.0 嵌套分组 + 目录整理重做 · 已与用户确认的决定（2026-11-08）

## 目录整理
- 只做「按分组把模组文件夹整体移动到分组文件夹」。**删除改名功能**（「分组并使用译名」按钮与 planner 的 outer 改名）。模组文件夹名不改。
- 分组文件夹名 = 分组名，Windows 不支持的字符直接去掉（不是替换）。已有分类文件夹改成与分组名一致（「0核心&基础模组」→「0基础模组」），改法：直接改名旧文件夹，再把不属于的移走。
- 嵌套分组 → 文件夹层级：`plugins/父/子/孙/<模组文件夹>`，最多 3 层。
- 拆嵌套：套在里面、有自己 manifest.json 的模组**全部拆出来**，放到自己分组对应的文件夹；与外层同组也搬到外层旁边。
  - 不拆：内层文件夹名为 plugins / BepInEx / patchers，或内外是同一个模组（同名 manifest）——这是模组自身打包结构（如 ESC 队友资料卡）。
- 分组跟概览列表那一行走；一行多插件分属不同组时按那一行（主插件）的分组。
- 没分组的 → 新建「未分组」文件夹并移入。
- 没生效的旧副本（`.dll1`、被跳过加载的同 GUID 旧版）跟同名模组进同一分组。
- 无 DLL 的模组（纯资源包、DLL 在 core 的 MonoDetour）→ 按 manifest 依赖找依赖它的模组，跟它的分组；找不到原位不动 + 提示。
- MMHOOK、MCEPack_* 永远不动，预览也不列。
- 空文件夹（含拆完后的空壳）单独一段列出，每个带删除按钮，确认后放回收站。
- 重名：后来的那个在文件夹名后加版本号（如「CptPICHU-TrueFinalAscent 3.0.0」），生效的保持原名。只在重名时改。
- 管理器自身照常参与、最后移动、不改名；实际移动完成后由我改工程部署路径。
- 只拦：链接/联接、路径超长、目标已有同名文件夹（重名规则之外）、BepInEx core / patchers。
- 预览顶部同时给「N 个文件夹 · 共 M 个模组」。

## 嵌套分组（视觉/交互）
- 概览列表：缩进 + 叠加色条（子分组左侧保留父分组色条，再加自己颜色色条，像文件夹树）；子分组标题略矮、字号略小。
- 同一分组内：主模组（直接成员）在上，子分组在下。
- 计数：父级计入所有子级；折叠父级连带收起子级，展开时恢复各子级自己的折叠状态。
- 最多 3 层。
- 颜色：各自选色，新建子分组默认用父分组颜色。
- 建子分组 / 挂上级：编辑器里「上级分组」下拉 + 列表里把分组标题拖到另一个标题上 + 分组标题菜单「新建子分组」。全部要防循环、防超 3 层。
- ModConfig 设置页左侧栏、快捷键页：与概览一致（缩进 + 色条）。

## 第二轮决定（2026-11-09）
- 套在别的模组里的模组：概览里各自一行、独立启停。
- 新建子分组：分组标题右键菜单（新建子分组 / 编辑 / 移到顶层 / 删除）；双击仍打开编辑。
- 删除带子分组的分组：子分组与成员上移一层（顶层被删 → 成员变未分组）。
- 导出兼容：含嵌套分组的方案/整合包，旧版拒绝导入（待核实旧版是否有可用的版本门槛）。
- 导出：含嵌套分组时 schemaVersion 写 2（旧版只认整数 1，会自然拒绝导入）；无嵌套时仍写 1，保持旧版可读。

## 第三轮需求（2026-11-09，用户新增）
- 首次打开 MCE 概览时，若 plugins 存在文件夹分层，弹窗询问是否「按现有文件夹层级智能分组」。细节待确认。
- 触发：只在分组列表为空（第一次启用加载 MCE）时弹一次；已有分组（例如导入整合包后的首次启动）不触发。
- 只读取文件夹、不改动任何文件夹；把现有文件夹布局「内化」为分组方案（建嵌套分组 + 模组归组）。
- 只算「纯分类文件夹」（自身无插件/manifest、只装模组文件夹），按层级建嵌套分组，最多 3 层；模组自己的文件夹与内嵌库不建组；根目录散装模组 → 未分组。
- 用户也勾了「工具页按钮」——已有分组时这个按钮做什么，待确认。
- 工具页不加按钮。
- 弹窗：用概览同款缩进+色条预览将生成的分组树与各组模组数，可展开看模组；「按此分组」/「不用了」。
- 确认即保存（不进草稿）。
- 颜色：顶层分配不同的大色系；子分组用同色系下的不同子色（如蓝色系下天蓝、灰蓝）。

## 第四轮决定（2026-11-09）
- 手动新建子分组也默认取父级色系里未用过的子色（与智能分组一致），可再改。
- 更新进度统计、管理中心模组选择器、日志窗口、依赖悬浮、方案变更核对、商店安装选分组：全部按层级显示。
- 嵌套模组启停：外层停用连带内层（普通模式与档案模式统一）。内层单独启停仍可。
- 调查发现：嵌套且有自己 manifest 的模组在概览里本来就是各自一行（FindManifest 止于最近的 manifest）。
- 重新启用外层：恢复到停用前的内层状态（停用时记下哪些内层开着）。
- 外层停用时不能单开内层：内层勾选框灰掉，悬停「外层模组 X 已停用」。
- 嵌套模组角标：加入现有角标行（StatusChip，8×8，琥珀色），悬停「内嵌于 X，建议用嵌套分组代替文件夹嵌套；目录整理会把它拆出来」。不弹窗、不进问题检查。
- 只给「有自己 manifest 的嵌套模组」加角标；打包结构（plugins/ BepInEx/ patchers/、同名 manifest）不算。
