# MCE 2.3.0：嵌套分组 + 目录整理重做 + 首次智能分组

## Context
用户在 2.2.13 实测后决定：目录整理只做「把模组文件夹整体移到分组文件夹」，不改模组文件夹名；同时引入**嵌套分组**（最多 3 层），用分组层级代替文件夹嵌套来管理附属/汉化模组，整理时把嵌套模组拆出来；首次加载 MCE 且没有任何分组时，弹窗把现有文件夹分层「内化」为分组方案。全部决定已逐条问过用户，记录在 `MODs/ModConfigEnhance/验证/2.3.0嵌套分组与整理重做/决定.md`（本计划以它为准）。

现状（调查结论）：所有分组消费方都假设单层——按全局 `order` 排序、按单个 `groupId` 归拢、只有一级标题、只按直接成员计数；`OverviewGroupEditor` 的回滚快照只拷 5 个字段（会丢新字段）；`ProfileChangeReview` 只比对 name/color/description/order；导出/导入都要求 `schemaVersion == 1`；分组标题没有右键菜单（但有 `UiMenuEntry` + `OverviewUi.PointerDropdown` 可复用）；嵌套且有自己 manifest 的模组本来就是独立一行（`OverviewCatalogue.FindManifest` 止于最近 manifest）。

## 一、数据模型（地基，先做）
- `src/Overview/OverviewModels.cs` `OverviewGroup` 加 `public string parentId = "";`。
- 新纯逻辑 `src/Overview/GroupTree.cs`：`Children/Ancestors/Depth(≤3)/Path("父 › 子")/Descendants/WouldCycle/CanAttach(child,parent)`、`Flatten()`（深度优先，同级按 `order`；成员先于子分组）、`SubtreeCount`、悬空 parentId 视为顶层。`order` 改为**同级内**有序（迁移：旧数据全是顶层，语义不变）。
- 颜色 `GroupPalette`：一组顶层大色系（蓝/绿/金/紫/红/青/灰…），每个色系 3–4 个子色；`NextTopColor(used)`、`NextChildColor(parentColor, siblingsUsed)`。手动新建子分组与智能分组都用它。
- 持久化/合并：`SaveScope` 整对象克隆、`SharedInformationRecovery` 按 id 三方合并、`DraftSignature` 已自动带新字段——只需核对；**修** `OverviewGroupEditor.cs:272` 回滚快照补 `parentId`；`ProfileChangeReview.cs:97` 比对补 `parentId`（显示「上级：A → B」）；`ProfilePendingState.GroupSignatures` 不改（按 id 已覆盖）。
- 删除带子分组的分组：子分组与成员上移一层（顶层被删→成员未分组、子分组变顶层）；清理 `collapsedGroups` 里的该 id。
- 导出：`OverviewProfileExport` / `PackWorkspaceInformation` / `OverviewState`——**存在任一非空 parentId 时 `schemaVersion` 写 2，否则写 1**；所有读取处（`RequireImportSchema`、`ReadStrictVersioned`、`PackWorkspaceInformation:24`、`OverviewRepository.cs:223/239`、`OverviewProfileStore:452/456/506`）改为接受 1 或 2。旧版只认 1 → 自然拒绝含嵌套的方案。

## 二、模组概览列表 `OverviewListView.cs`
- 排序改为按 `GroupTree.Flatten` 的位置（替换 `GroupOrder` 平铺排序 :451/:715），同一分组内直接成员在上、子分组在下。
- 标题 `BuildGroupHeader`：按深度缩进（每级 14px），左侧依次画祖先色条 + 自己色条（各 3px、间隔 2px），子分组标题高 28（顶层 32）、字号 20→18→17。计数为子树总数。
- 折叠：父折叠时子树全隐（`_visible` 过滤改为「任一祖先或自身折叠」），子分组各自折叠状态保留。
- 空分组（作者模式）放到树中自己的位置，而不是全部追加到末尾。
- 右键分组标题（新增，用 `UiMenuEntry` + `OverviewUi.PointerDropdown`）：新建子分组 / 编辑 / 移到顶层 / 删除；超 3 层或会成环时菜单项置灰并说明。双击照旧打开编辑。
- 拖拽：作者模式下分组标题可拖；拖到另一标题上 = 挂为其子分组（校验深度/成环，失败在状态栏说明）；拖到模组行间 = 照旧移动模组。模组行左侧色条改为祖先色条叠加。
- 嵌套模组角标：`StatusChip` 新槽（琥珀色），条件「行 PackageRoot 位于另一个有 manifest 的模组目录之下，且不是打包结构（内层目录名 plugins/BepInEx/patchers 或同名 manifest）」；悬停「内嵌于 X，建议用嵌套分组代替文件夹嵌套；目录整理会把它拆出来」。标题预留按 `StatusChip.Reserve(n)`。

## 三、分组编辑器 `OverviewGroupEditor.cs` / 管理页
- 新增「上级分组」下拉（`OverviewUi.Choose`，选项为路径「父 › 子」，排除自身子树与会超 3 层的项）。
- 嵌入式左栏按树显示（缩进），上/下移动在同级内进行。
- 新建子分组默认色走 `GroupPalette.NextChildColor`；新建顶层走 `NextTopColor`。

## 四、其他按分组显示的地方（全部按层级）
- ModConfig 侧栏 `ModConfigSidebarWidgets.Groups.cs`（`MakeGroupHeader` 缩进+叠加色条、`RefreshGroupLabels` 子树计数、`ApplyGroupVisibility` 祖先折叠、`ApplyPinOrder` 按树序）与 `ModConfigSidebarWidgets.cs` 行色条。
- 快捷键页 `OverviewHotkeyView.cs:154-165`、`JumpTo` 展开全部祖先。
- 管理中心模组选择器 `ManagementModSelector.cs:42-56`、日志窗口 `LogWindow.cs:221-232`、依赖悬浮 `OverviewDependencyHints.Components.cs:76-86`、更新进度 `OverviewListView.CheckProgress.cs` / `ThunderstoreUpdateService.cs`：标题用缩进或「父 › 子」路径，排序用树序，计数含子树。
- 方案变更核对 `ProfileChangeReview` / `OverviewUi.ProfileReview.cs:63`：组名显示路径，排序用树序。
- 商店安装选分组 `ShopWindow.ChooseGroup`（:282-290）：选项显示路径；「新建…」可选上级。

## 五、嵌套模组启停 `ModToggleService.cs`
- 统一为「外层停用连带内层」：普通模式 `BuildPlan` 停用外层时，把其目录下所有有自己 manifest 的内层模组也加入计划（档案模式本来就递归，保持）。
- 停用时把当时开着的内层记到外层的规则里（新字段 `OverviewModRule.nestedEnabledBeforeDisable`，GUID 列表）；重新启用外层时只恢复这些。
- 外层停用时内层勾选框不可用，`ToggleReason`「外层模组 X 已停用」。
- `CheckPackageDependencies`（:626-677）按包判定 active 时排除内层包自己的文件。

## 六、目录整理重做（worker + 插件）
- 删除改名：去掉「预览分组并使用译名」按钮（`OverviewPage.Management.cs:218`）、`InstallationLayoutMode.GroupAndTranslatedOuterFolder` 路径、planner 的 outer 改名（模组文件夹名恒为原名）。
- 协议：`LayoutQueueGroup` 加 `ParentId`；`LayoutQueueMod` 由「一行」发送（行 GUID → 行所属分组；行内其他插件跟随），另带 `PackageRoot`。
- Planner：分组文件夹路径 = 分组名链（去掉 Windows 非法字符），最多 3 层；单元 = 每个有自己 manifest 的模组目录（**嵌套的拆出来**，打包结构不拆）；无 manifest 的 DLL 目录照旧作单元。
  - 已有分类文件夹与分组名不一致时：**改名旧文件夹**为分组路径（一次 rename），再移走不属于的。
  - 未分组 → 新建「未分组」文件夹移入。
  - 未生效旧副本（`.dll1`、同 GUID 被跳过的版本）跟同名模组的分组。
  - 无 DLL 包（纯资源、DLL 在 core）：按 manifest 依赖反查依赖它的模组，跟其分组；找不到原位不动+提示。
  - 永不碰：MMHOOK、MCEPack_*、BepInEx core/patchers。
  - 重名：后到的文件夹名后加「 版本号」，生效的保持原名；只在重名时。
  - 管理器自身照常移动、最后移动、不改名。
  - 仍拦：链接/联接、路径超长、目标已被非重名占用。
  - 空文件夹与拆后空壳：列入 Tree（新 `Disposition` 值 `Empty`），不移动。
- 执行：移动顺序「先改名分类文件夹 → 由深到浅拆内层 → 其余 → 管理器」；回退按逆序。保留 2.2.13 的 `LayoutPaths.OldPath`。
- 预览 UI `LayoutReviewView`：分组卡按嵌套分组缩进成树；标签改为「移入 / 原位 / 未分组 / 拆出 / 空文件夹 / 不动」；顶部「N 个文件夹 · 共 M 个模组」；空文件夹卡每行一个「删除」按钮 → 确认 → 回收站（插件侧 `Microsoft.VisualBasic.FileIO` 不可用时用 Shell `SHFileOperation`，先核实 Mono 可用性，不行就走 worker 的回收站实现或询问用户）。
- 部署路径：实际整理移动完成后，改 `ModConfigEnhance.csproj` `DeployDir` 到 MCE 新位置（单独一步，届时向用户报告）。

## 七、首次智能分组
- 触发：概览首次进入且 `State.groups` 为空、plugins 下存在至少一个「纯分类文件夹」时弹一次；记 `ui.json` 标记，选「不用了」后不再弹。已有分组（如导入整合包）不触发。
- 只读扫描：纯分类文件夹（自身无插件/manifest、只装子目录）按层级建嵌套分组（≤3 层，更深的并入第 3 层）；模组目录内嵌不建组；根目录散装 → 未分组。颜色顶层 `NextTopColor`、子级 `NextChildColor`。
- 弹窗：复用 `LayoutReviewView` 的卡片/缩进/色条样式预览分组树与每组模组数，可展开；「按此分组」/「不用了」。确认即写入分组并保存（`SavePackInformation(Groups)` + 成员 `groupId`）。
