# 2.3.0 代码审查结论（2026-11-09）

审查范围：`备份/2.3.0_20261109_嵌套分组前` → 当前源码（`2.3.0.diff`，30 个改动文件 + 9 个新文件）。
第 1 组（分组树与持久化）由子代理审，主线程逐条读源码复核；其余部分（嵌套启停、智能分组、规划器、执行回退、其他视图）由主线程直接审。第二轮其余 4 个子代理因网关 402/429 失败，无结果。

## 高（会坏数据或打不开）

1. **已应用快照写成 schemaVersion 2 后，下次加载直接抛错，概览打不开**
   `OverviewRepository.Applied.cs:45` 仍要求 `snapshot.schemaVersion != 1` 就抛。`OverviewProfileStore.cs:495` 让含嵌套的方案在盘上写 2，`Load`（:452）只校验不归一，内存里就是 2；`ApplyProfileTransaction`（:168 `Clone(ViewedProfile)` → :190 写盘）与快照缺失分支（:51-52）都会把 2 写进 `applied-profile.json`。触发：方案有子分组、做过一次完整保存后再应用一次 → 重启后 Reload 抛「已应用方案记录与方案索引不一致」。同类：`DraftRecovery.cs:125` 的 `applied.schemaVersion != 1` 会让历史修复对嵌套方案静默失效。
2. **新版导入自己发布的、含嵌套分组的非完整整合包会失败**
   `Updater/PackImports.cs:465` 的 `ProjectDefaults` 仍硬要求 profile.json 为 1（:271 非 complete 时进入）。违背「只让旧版拒绝」的决定。
3. **首次智能分组「按此分组」后模组归组可能全部丢失**
   （推演成立，需实测确认；编辑器 `OverviewGroupEditor.cs:310-316` 在 2.3.0 之前就是同一写法，可能是旧问题，智能分组只是把它放大了。）
   `OverviewPage.SmartGrouping.cs:144` 用 `_repo.GetRule(guid).groupId = …`。没有分组的新方案里 `State.mods` 基本为空，`GetRule` 返回的是 `_temporaryRules` 里的临时规则（`OverviewRepository.cs:99-106`）；随后 `SavePackInformation(Groups)`（`SaveScope.cs:18-24`）只遍历 `State.mods`，不调 `MergeEditedRules`。结果：分组被保存，成员归属没保存；紧接着 `_list?.Reload()` 重扫后，只要中间发生过一次 `Reload`（`Profiles.cs:129` 清空临时规则），成员就全回到未分组。现装的 `pack-information.json` 里 65 条规则都是此前其它保存路径并入的，新装/空方案才会踩到——恰好就是智能分组唯一会出现的场景。
4. **整理与智能分组都不认 MCE 自己停用过的模组（`manifest.json.old`）**
   `Updater/GroupLayoutPlanner.cs:70` 与 `OverviewPage.SmartGrouping.cs:54` 只看 `manifest.json`；MCE 停用时会把 manifest 改名为 `manifest.json.old`、DLL 改为 `.dll.d`（`ModToggleService.cs:356-359`）。插件侧 `OverviewCatalogue.FindManifest`（:250）是认 `.old` 的，两边口径不一致。推演（模组 `X/`，DLL 在 `X/plugins/`，现装 63 个包里 14 个是这种结构）：
   - 规划器：`X` 无 manifest、自身无 DLL → 被归为分类文件夹；`X/plugins` 有 DLL → 被当成独立包。概览行的 `PackageRoot` 是 `X`，匹配不到 `X/plugins`（`GroupFolderPlanner.cs:197`）→ 该包无行、无 manifest 名 → `NoGroupKnown`，原位不动。结果是**停用中的模组不跟着自己的分组走**，预览里显示成「没有插件，也没有模组依赖它」，文案也是错的。
   - 智能分组：`X` 被当成分类文件夹 → **生成一个以该模组文件夹命名的空分组**（成员映射按 `X` 找不到 `X/plugins` 这个键，`SmartGrouping.cs:144` 起），且该模组本身不进任何分组。
   DLL 直接在根层的停用模组（如现装 `[依赖]PLL地图与群系库-PLL_Library/`）会被当 DLL 包，不受影响，只是丢了 manifest 名与依赖信息。

## 中

5. **嵌套模组「外层停用连带内层」只做在草稿层，计划第五节的 `ModToggleService` 一行没改**
   落盘时 `ModToggleService.BuildPlan` 只按 `mod.AssemblyPaths` 逐个改 DLL 名（:300-309）+ 本包 `manifest.json`（:354-360）。连带之所以「看起来能用」，是因为 `SetWithNested` 把内层也写成了独立目标。但：
   - 内层若 `CanToggle == false`（例如来源冲突、含 patchers），`SetPlannedEnabled`（`Profiles.cs:321`）只校验外层，递归进内层时不校验；落盘时 `BuildPlan` 对内层抛 `ToggleReason`，**外层的停用也一起失败**，用户只看到一句报错。
   - 方案从别处导入、或在旧版本里只记了外层停用（没有内层条目）时，落盘只停外层 DLL，内层照常加载——与「外层停用连带内层」相悖。计划里「普通模式 BuildPlan 停用外层时把内层也加入计划」正是为这种情况，未实现。
   - `CheckPackageDependencies` 排除内层文件（计划第五节）也未做。
6. **`nestedEnabled` 会被导出进作者方案**
   `OverviewProfileModels.cs:73` 新字段跟随 `OverviewProfileMod` 序列化；作者预设导出只剥离了 `copy`（2.2.2 的副本选择键），没剥离 `nestedEnabled`。它是本机启停记忆，分发出去后别人的机器上 GUID 集合不同，恢复时会按别人的记录恢复内层。影响小，但属于「个人字段外泄」同类问题。
7. **列表菜单里删除/挂接/新建分组失败时不回滚内存状态**（第 1 组发现，已复核）
   `OverviewListView.Groups.cs:94-97`、`:116-121`、`:131` 先改 `State` 再保存，catch 只报状态；`SavePackInformation` 只回滚磁盘与 `_savedDraftProfile`。保存失败后界面已按改动显示，下次完整保存会把用户以为失败的改动提交上去。编辑器 `Commit` 有完整回滚，新加的三个入口没有。
8. **回退会删掉用户原本就有的空分组文件夹**
   `Installer.cs:155-160`：`created` 取的是所有 `move.To` 的全部祖先目录，不区分「整理新建的」和「原本就存在的」。用户原有一个空的 `plugins/3玩法模组/`（例如等着放东西），整理把模组移进去后失败回退，模组移走、该目录变空 → 被删。注释说「Folders the organizer created」，实现不符。

## 低

9. **删除分组后上移的子分组会和新兄弟交错**（`GroupTree.cs:158-161`，复核成立）：子分组保留旧 order，与新兄弟同值时按 GUID 排；注释承诺「占被删分组的位置」未实现。
10. **编辑器删除确认文案仍是「组内模组会移到未分组」**（`OverviewGroupEditor.cs:273`），与实际「上移一层」、与列表菜单文案都不一致。
11. **金色系与棕色系共用 `#E0B29B`**（`GroupPalette.cs:18/23`），`FamilyOf` 取先命中 → 棕色子组再建孙组会从金色系取色。

## 复核过、没有问题的
- 深度≤3：`CanAttach` 用 `Depth(parent)+Height(child)`；编辑器上级下拉排除自身子树与超层候选；拖拽/移到顶层都走 `Attach`。
- 损坏数据（自引用/环/悬空 parentId）按顶层处理，遍历有 seen 集合，不会死循环。
- `GroupTree.Remove` 同时处理成员 groupId、子分组 parentId、collapsedGroups。
- 列表排序已全部走 `Groups.Position`；更新进度、侧栏、快捷键页传入的是树序与路径。
- 规划器移动顺序：分类文件夹改名在前（`mapped` 循环），之后的移动用 `sim.Current` 换算后的路径；嵌套包由深到浅、管理器最后。
- 插件侧嵌套判定 `NestedMods` 与 worker 侧 `IsPackaging` 规则一致（plugins/BepInEx/patchers、同名 manifest）。
- 外层停用时内层勾选框置灰与悬停提示已接线（`OverviewListView.cs:552-553`）。
