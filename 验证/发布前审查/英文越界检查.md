# 英文界面按钮/标签越界静态审查（ModConfigEnhance 2.3.8）

审查方式：只读静态审查，未改任何源码，未实机运行。所有宽度均为**估算**。
估算方法：字体用 `MceRegularFont`（Arial → Segoe UI → Noto Sans，Windows 上即 Arial）。用 Arial 真实字宽（PIL 量出）乘字号，再加按钮文字左右边距 5+5=10 px。该口径折算后约 0.50~0.53 × 字号 / 字符，比任务里的 0.55 略窄。中文按 1.0 × 字号 / 字符。
范围：约 120 处字面量宽度的 `Button(...)`，另手工核对约 85 处（商店窗口 `Button` 辅助函数、日志窗口 `Btn`、对话框、更新队列等）。
按你的补充，2.3.8 已并入下拉的「管理方案」独立按钮已跳过。

## 结论

**英文界面基本可以直接用，但不是零成本。** 绝大多数按钮宽度是按中文调的，英文平均多占约 1.3~1.6 倍，其中多数仍有余量，或自带按文字测量宽度，或自动缩小。真正越界的只有 3~4 处，另有一批「偏紧」（估算 90~100%），建议在发布前顺手放宽。没有发现会让英文按钮整体互相覆盖的大面积重叠；主工具栏会自动把放不下的项收进「更多」，不会溢出。

## 按钮文字的溢出方式（先看这个）

`OverviewUi.Button`（`Overview/OverviewUi.cs:121-149`）：

| 项 | 实际值 |
|---|---|
| 字号 | `Math.Min(30, height * .42f)`（`:137`）。高 36 为 15.1，高 34 为 14.3，高 32 为 13.4，高 28 为 11.8 |
| 自动缩小 | **默认关闭**：`enableAutoSizing = false`（`:137`） |
| 换行 | `NoWrap`（`:138`） |
| 溢出模式 | `TextOverflowModes.Overflow`（`:138`）。**默认既不截断也不加省略号** |
| 对齐 | `Midline`，文字居中（`:139`） |
| 文字内边距 | `caption.margin = (5,0,5,0)`（`:141`） |
| 遮罩 | 代码里没有给按钮加 `RectMask2D`；`:129` 还销毁了本地化组件，`MceRegularFont.ApplyDefault` 会换掉字体和材质（可能丢掉原按钮的 stencil） |

**后果**：文字超宽时，**以按钮中心向左右两边各溢出一半，直接画在按钮外**。可能压到邻居按钮或标签，也可能越出面板边缘。没有缩小，也没有省略号。「是否被预制体的 stencil 裁掉」代码里无法确认，**实机待验证**。

`OverviewButtonLayout.Refresh`（`:540-548`）只在 `!enableAutoSizing` 时才重设字号，说明默认按钮是固定字号。

## 主工具栏（`OverviewPage.Toolbar.cs`）：不会溢出，但英文会把更多项挤进「更多」

按钮宽度按文字测量，所以不越界，但总宽变大。估算（Arial，14.3 号）：
- 中文：工具栏已用约 1457 + 帮助区约 166，合计约 1635 px。
- 英文：约 1627 + 172，合计约 1810 px，多约 175 px（+11%）。
- 英文下变宽的几项：`Save configuration` 143（中文 92）、`Sources and updates` 210（146）、`Management center` 152（105）、`Language` 88（76）。

可用宽度是 `框架宽-40`。按上述估算，英文要约 1850 px 以上才能全部露出（取决于画布缩放，估算）。放不下时按 `CollapseOrder` 依次收进「更多」：`import` 和 `shop`（0）→ `sources`（1）→ `refresh`（2）→ `language`（4）→ …。**结果是英文下「Mod store / Import / Sources and updates」最先被折叠，不是越界。** 是否可接受请产品侧定。

## 建议修法（按改动量由小到大）

1. **改措辞/个别加宽（几乎零风险，建议先做）**
   - `ShopWindow.cs:190` 的 `Core / preloader updates`：改成 `Core updates`，或把侧栏过滤按钮宽度 `left-36` 放宽 10。
   - `SourceUi.cs:261` 的 `Identify manually`：改成 `Identify`，或把宽度 100→124，同时把「Mark as local」起点右移 24。
   - `OverviewPage.Profiles.cs:352` 的组标签宽 52→64，并把 `actionLeft = detailX + 56` 改为 `+ 72`。
   - `PublishWizard.cs:123`：把上限 `Mathf.Min(360, …)` 放到 460；或把按钮英文改短成 `Format: Complete store ZIP (fixed deps)`；也可以让 `FormatLabel` 在按钮里用短词。
   - `PublishFilePreview.cs:129/128`：宽 140/128 → 164/148；`PublishFilePreview.cs:199/200`：半宽改为 `Mathf.Max(half, 150)`，窄了就换行。
   - `OverviewPage.Packs.cs:51`、`SourceUi.cs:202`、`LogWindow.cs:105/135/571`、`ShopWindow.cs:277`、`OverviewPage.Profiles.cs:377`：各加宽 12~20，或字号降 1。
2. **给 `OverviewUi.Button` 加统一兜底（改一处全局受益，推荐）**：在 `OverviewButtonLayout.Refresh`（已随尺寸变化触发）里，用 `caption.GetPreferredValues(caption.text).x` 与 `rect.width - 10` 比较，超宽就把 `fontSize` 按比例缩小（下限约 0.78×，约 11 号），仍超则改 `Ellipsis` 并挂悬停提示。**注意**：这会改变所有固定宽度按钮，且需避开已手动开启自动缩小的按钮，改前请用户确认。
3. **把固定宽度的按钮换成按文字测量宽度**：沿用 `PublishWizard.Button` / `form.Button` 的写法，`Mathf.Clamp(preferred + 26, 最小, 最大)`，涉及商店窗口 `Button` 辅助函数、日志窗口 `Btn`、`SourceUi`。工作量较大，需同时调整相邻按钮的 x 偏移。
4. **按钮一律开启自动缩小**：最简单粗暴，把 `Button` 里 `enableAutoSizing` 改成 `true`，`fontSizeMin = size*.78`、`fontSizeMax = size`。优点是一行改动；缺点是不同按钮字号会不一致，需实机看效果。

## 未覆盖/不确定项

- 未实机量字宽，全部为估算（Arial 字宽 + 10 px 边距，±8% 误差）。
- 未逐条审阅 `Loc.F` 的动态格式文本（含用户内容、模组名、版本号）和列表行 `Label`。它们走 `Ellipsis`（行内）或 `Overflow`（表头）；已确认表头里只有 `Version/Author/Description/Name`，英文都不超宽。
- 按钮溢出文字是否被预制体的遮罩/stencil 裁掉，需要实机确认。
- 实际窗口宽度取决于游戏分辨率和画布缩放，标注「窗口宽度依赖」的项需要在 1280/1600/1920 三档各看一次。
