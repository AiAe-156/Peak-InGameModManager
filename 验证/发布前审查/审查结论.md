# MCE 发布前审查（2026-11-09，基于 2.3.7 源码，只读）

> 两个后台子代理因网关 402 中断，以下全部为主线程直接核查。数字由本目录 `translation_coverage.py`、`twoarg_zhtw.py` 实际统计。

## 结论

**现在不具备发布条件。** 代码本身构建 0/0、回归 23/23；主要缺口在文档和文本：

1. 内置帮助停在 2.1，2.2–2.3.7 的大部分功能没写（见下表）。
2. 翻译：约 400 处界面文字不会进入翻译导出，其中 78 处在繁中下显示简体，48 处是硬编码中文（英文界面下也显示中文，集中在日志窗口和整合包空间管理）。
3. 整合包流程能走通，有回归覆盖；但没有针对 2.2 之后新状态（资源包、组件 `.dll.d` 停用、管理器档案）做过切换实测。

## 二、翻译模块与现版本的耦合

**机制（核实）**：`Loc.T(en, 简, 繁)` 先查当前语言文件里以英文原文为键的条目（`_inlineSnapshot`），查不到就用调用处自带的三语文本。内置语言文件由词条表 `AllInlineTerms`（`Loc.*Terms.cs`，共 2166 条）生成，**翻译导出也只导出这张表**。

所以「模组自带英文原文 + 简中/繁中」这条设计，**对写成三参数 `T()` 的文字是成立的**：语言文件缺失也能正确显示三语。问题出在下面三类：

| 类别 | 数量 | 影响 |
|---|---|---|
| 三参数 `T/F` 但英文不在词条表 | 329 处 | 显示正确；但**导出给翻译者时没有这些条目**，别的语言无法翻译。集中在 2.2 之后新增的界面（组件详情、整理窗口、更新记录、启停等） |
| 两参数 `T(英, 中)`（繁中位置填的是简中） | 791 处，其中 **78 处**英文不在词条表 | 这 78 处在**繁中界面显示简体**。最多的是方案保存（20）、分组菜单与子分组（19+11）、管理中心（7）、标签筛选（7） |
| 硬编码中文、没走 `T/F` | 48 处 | **英文界面也显示中文**。集中在日志窗口（等级/模组按钮、暂停刷新、跟随、新增 N 条）和整合包空间管理页（`OverviewPage.Packs.cs:83-87` 等），另有部分整合包任务按钮（「重试恢复原环境」「返回空间管理」「确认移入回收区」） |
| 更新助手 `Updater/WorkerLanguage.cs` | 有独立三语表 | 正常 |
| 桌面窗口 `Desktop/` | 29 行含中文 | 待逐条确认是否已走 `--language` |

结论：**翻译模块本身没坏，也没有和新功能冲突**；是 2.2 之后新增界面没有把文字登记进词条表，部分甚至没有三语。

**最小改法**：
1. 写一个生成脚本，扫描源码里全部三参数 `T/F`，把不在词条表的条目自动追加进一个新的 `Loc.Release23Terms.cs`，并接入 `AllInlineTerms`。
2. 两参数 `T` 的 78 处补繁中（改成三参数）。
3. 48 处硬编码中文改成三参数 `T`。
4. 加一条源码断言：词条表必须覆盖全部三参数调用、禁止新增两参数和硬编码中文，以后新功能漏登记会直接报错。

## 三、整合包导入导出

| 流程 | 入口 | 执行 | 现状 |
|---|---|---|---|
| 导入整合包 | 工具条「导入」→「导入整合包」，或管理中心「整合包」页 | worker `PackQueue`：preview-import → confirm-download → confirm-import | 有回归（`PackLibraryChecks`、`RealPackRoundTrip`） |
| 切换整合包 | 整合包库 → 选中 → 切换 | preview-switch → confirm-switch，等游戏退出 | 有失败恢复（retry-recovery / retry-switch） |
| 保存临时整合包 | 整合包页 | preview-adopt / confirm-adopt | 有完成提示 |
| 升级整合包环境 | 整合包页 | preview-upgrade-environment | — |
| 空间管理 / 回收区 | 整合包页「空间管理」 | maintenance-preview / maintenance-execute | 页面文字是硬编码中文 |
| 导出方案 | 管理中心「方案」→ 导出 | `OverviewProfileExport` | 有嵌套分组时写 schemaVersion 2（已按 2.3.0 适配） |
| 发布整合包 | 发布向导 | `PackPublisher` | `release.json` 仍写 schemaVersion 1（这是包索引，不含分组，符合 2.3.0 规则） |
| 本地导入模组 | 工具条「导入本地 DLL / ZIP / 文件夹」 | worker 新安装核心 | 有回归 |

`PackTransactions.Canonical` 已改用 `PluginFileNames.OriginalPath`，能识别任意 `.dll.*` 停用名。**未核实**：切换整合包时对资源包（`manifest.json.old`）、组件 `.dll.d`、r2modman 档案布局的处理，现有回归没有覆盖这几种状态，需要实测或补夹具。

## 四、本轮顺带修复（未部署）

- **橙色角标在不同行位置不同**：原因不是两个角标没合并。每一行只有一个橙色「未保存」角标，但车道右边缘跟着本行的来源标签（商店/本地/待定，宽度不同或不显示）和「+」按钮浮动，所以同一个角标在不同行的横坐标不一样。已改为每行用同一个右边缘（按最宽的来源标签预留），编译 0/0，**未部署、未回归**。

## 建议的发布前工作（按顺序）

1. 翻译补齐（上面四步，可以脚本化，工作量主要是 78 处繁中和 48 处硬编码的翻译）。
2. 帮助文档补 2.2–2.3.7：新增一页「界面与角标图例」，更新 changelog，修正「必需依赖受保护」等过时表述，加术语表。三语同步。
3. 整合包：资源包 / 组件停用 / 档案布局下的切换各实测一次，或补夹具。
4. 改名（等用户定名后）：显示名、manifest `name`、README、帮助、语言文件头。GUID `com.aiae.modconfigenhance` 与配置目录是否跟着改要单独决定——改 GUID 会让现有用户的配置和方案读不到。
