## 旧补审原 8 条失败逐项核验

旧文件 `验证/SourceFinalReview/Program.cs` 未改，原始断言完整保留。旧脚本混合现行行为、期望不变量和“旧缺陷仍存在”的检测，不可将其退出码直接当当前验收。原始 8 条对应如下：

| 原失败 | 判定及本轮处理 |
|---|---|
| export 不应携带 explicitLocal | 与当前明确 Local 可随发布传递策略相反；不修改生产导出。SourceUpdateChecks 现行 Local 策略回归继续通过。 |
| 接收端不应识别 published explicitLocal | 同上，现行策略就是识别；不削弱用户/作者明确 Local。 |
| 接收端个人 auto 应覆盖 published Local | 与当前 `Get` 和 ExplicitLocal 明确约束相反：auto 不属于个人授权；必须显式 Store 才覆盖 published Local。现行专门断言验证个人 Store 可以覆盖。 |
| auto 后 Discover 应恢复 published Local 的商店身份 | 同上；不通过猜测覆盖明确 Local。 |
| stale derived 身份缺目录仍应自动匹配 | **实际 bug，已修**：Apply 只把 derived 当提示，须按当前目录和原始本地证据重新 Resolve，失败立即剥离提示，恢复原始身份并重新匹配。原断言现在通过。 |
| force 仍无法清除 stale derived | **实际 bug，已修**：同一 Apply 重验证在 Discover 中生效，发现成功会持久化正确映射。原断言现在通过。 |
| 恢复 auto 后 TeamX 污染导致 Pending | **实际 bug，已修**：Set 清除本安装指纹的派生缓存与 miss 并持久化；Apply 更新解析成功的身份；Discover 不把个人 UserChoice 写入 derived。原断言现在通过。 |
| force 后仍无法恢复 Alice | **实际 bug，已修**：同上；原断言现在通过。 |

没有修改 StoreIdentityIndex 的来源信任边界：原始显式身份无效仍拒绝，不能用相似名称替换；只有可替换缓存提示能剥离。手动映射继续依安装指纹有效，显式 Local 继续优先；MonoDetour 清单证据不被缓存制造。

旧补审本轮实际 **41/48，7 失败**（`integration-oldreview.log`，退出码 1），不报全绿：前四条仍是上述策略冲突；另外三条原来是 PASS 的“旧缺陷存在”探针，现在因修复而失败，分别为“Ghost 缓存必须投影成 SourceNamespace=Ghost”“手动 TeamX 必须复制进 derived”“auto 后 derived 必须仍保存 TeamX”。三者正好与本轮正确行为相反。新的独立生产断言验证这些缺陷已消失，不删除/反转旧脚本以凑通过。

旧脚本还记录单上下文 cache 轮换、全局失败 summary、分类提示覆盖等 OBSERVED/FINDING；它们不属于本轮原 8 条失败或本次窄任务，不宣称在此修复。缓存上下文策略未扩大为多整合包持久存储。
